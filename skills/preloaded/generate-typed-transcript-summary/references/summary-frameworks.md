# 类型化总结框架

## 自动判型与模板路由

先阅读当前转写代次的完整内容，再从以下五类中选择一个主类型；判型完成后才能组织总结章节。主类型决定唯一的二级章节骨架，次类型只能作为章节内的三级小节。

| 类型 | 内容主目的 | 关键判定信号 | 优先排除 |
|---|---|---|---|
| `interview` 人物访谈 | 理解一个人物的经历、选择和观点 | 人物经历或决策是问答中心 | 团队围绕具体事项形成决策时改判 `meeting` |
| `training` 培训课程 | 帮助受众系统学习并应用知识 | 明确目标、受众、知识结构、步骤、示例或练习 | 单纯汇报方案并推动工作不算培训 |
| `salon` 沙龙分享 | 交流观点、案例和探索方向 | 开放分享、观点交锋、问答或探索为主 | 出现明确工作事项、决策或行动闭环时改判 `meeting` |
| `meeting` 会议 | 推进共同工作并形成决定或后续安排 | 议题、事实、方案、约束、决策、待决策事项或行动项 | 只有寒暄、公开分享或泛讨论时不判会议 |
| `general` 通用内容 | 无法稳定归入专属类型 | 主目的混合、信息不足或置信度不足 | 不强套专属模板 |

判型规则：

- 先看主要产出是学习、人物理解、观点交流还是工作推进；工作推进优先选择 `meeting`，即使包含讲解、汇报或问答。
- 置信度低于 `0.75`，或前两候选差距小于 `0.10` 时选择 `general`。
- 会议判型至少引用分布在转写不同位置的两段原文；不能只凭“开会”“汇报”等开场词。
- 标题、文件名、上传类型只能作为同分时的弱提示，不得单独决定主类型。

## `interview` 人物访谈

```markdown
## 一、人物背景
## 二、经历与决策
## 三、核心观点
## 四、原则与思维模型
## 五、案例与证据
## 六、反思与边界
```

## `training` 培训课程

```markdown
## 一、学习目标、适用对象与前置知识
## 二、培训内容体系
## 三、核心知识要点与原文金句
## 四、方法、操作步骤与判断标准
## 五、案例、工具使用与互动问答
## 六、练习、自测与应用清单
```

| 章节 | 必须回答 | 生成边界 |
|---|---|---|
| 学习目标、适用对象与前置知识 | 学完能解决什么问题、适合谁、开始前需要具备什么 | 只写原文明示或可由原文直接归纳的内容，不根据课程主题猜测受众和基础 |
| 培训内容体系 | 讲师按照什么逻辑展开课程，各部分讲了哪些知识 | 按真实授课顺序详细还原；背景引入、理论讲解、案例分析、实操演示、互动问答只是常见顺序，不得强行补齐；案例和工具在首次出现的位置保留必要细节 |
| 核心知识要点与原文金句 | 学员必须记住哪些结论，讲师有哪些值得保留的原话 | 知识要点做忠实提炼；金句必须逐字来自原文，不得改写成伪引语；没有合适原话时不生成金句 |
| 方法、操作步骤与判断标准 | 在什么场景下，准备什么，按什么步骤操作，如何判断完成 | 原文缺少前置条件、步骤、标准或结果时，对应内容留空，不用常识补全流程 |
| 案例、工具使用与互动问答 | 案例的背景、过程、结果是什么，工具如何使用，现场问答解决了什么 | 作为证据层补足前文未展开的具体细节，不重复结论；只记录真实出现的案例、操作和问答 |
| 练习、自测与应用清单 | 讲师布置了什么练习、自测或应用任务 | 只收录原文明示的任务及检查方式，不自行设计题目、答案或应用建议 |

培训模板规则：

- 「培训内容体系」是主干，按授课逻辑组织，不按知识类型重新打散内容。
- 每个非空内容块必须关联当前转写代次的原文证据；事实、数字、案例结果、工具操作和引语均不得脱离证据。
- 固定章节必须保留。原文没有可靠内容时，该章节的 `blocks` 必须为 `[]`；不得输出“未提及”“信息不足”“无”等占位话术，也不得使用常识或推测补齐。

## `salon` 沙龙分享

```markdown
## 一、活动与参与者
## 二、议题与观点
## 三、观点交锋
## 四、案例与问答
## 五、共识与分歧
## 六、探索方向
```

## `meeting` 会议

会议总结用于快速看懂一场会议讲了什么、形成了哪些决定、接下来需要做什么。它按单个视频组织完整内容，不替代按议题片段生成的工作事项、会议主题或跨视频演变，也不能作为决策、行动或状态变化的唯一证据。

```markdown
## 一、会议总结
## 二、会议基本信息
## 三、关键议题和共识
## 四、会议分歧点
## 五、会议讨论详情
## 六、待办事项
## 七、遗留和搁置议题
## 八、其他
```

| 章节 | 必须回答 | 生成边界 |
|---|---|---|
| 会议总结 | 会议试图解决的核心问题、主要共识或最终定调是什么 | 采用电梯演讲式总结和精炼语言，原则上不超过 140 字；确保未参会者仅阅读本章即可掌握会议精神 |
| 会议基本信息 | 何时召开、谁参加、属于什么会议类型 | 至少包含参会时间、参会人员和会议类型；只使用原文或视频元数据明示的信息，缺失项标记“会议中未明确” |
| 关键议题和共识 | 讨论了哪些关键议题、拍板了什么、为何如此决定 | 按议题组织；每项包含决策内容、决策逻辑，可选填后续影响；提议、倾向和已定共识必须明确区分 |
| 会议分歧点 | 哪些观点或方案存在分歧、各方依据是什么、是否已解决 | 只记录原文明示的分歧；已形成共识的内容归入“关键议题和共识” |
| 会议讨论详情 | 围绕各议题具体讨论了什么 | 覆盖会议全部实质内容并按逻辑组织，不按发言顺序逐句复述；区分事实、观点、方案和约束 |
| 待办事项 | 要完成什么、由谁负责、何时完成 | 遵循 SMART 原则；每项包含事项描述、负责人和截止时间，可选填优先级与状态；建议不等于待办，缺失项标记“会议中未明确” |
| 遗留和搁置议题 | 哪些内容不在本次讨论、暂缓执行或因信息不足延后决策 | 每项包含搁置内容、搁置原因和后续计划；不得把已明确否决的内容写成搁置议题 |
| 其他 | 还有哪些信息同步或补充 | 不重复前述章节；没有其他信息时写“无” |

会议模板规则：

- 除直接读取的会议名称和时间外，每个可展示结论必须关联至少一个当前转写版本的原文片段和时间位置。
- 关键议题、共识、分歧、待办与遗留议题保持各自语义边界，不因表述相近而合并。
- 固定章节没有可靠内容时仍保留章节；“其他”写“无”，其余章节以“会议中未明确”说明缺失，不补写套话或常识。
- 用户修正视频为会议场景后，只重新生成会议总结和会议应用视图，不重做转写或五类知识。
- 会议总结保存在现有视频智能总结位置（`typed_summary` 内容页），不生成第二份会议纪要，不新增知识类型。

## `general` 通用内容

```markdown
## 一、定位与问题
## 二、主张与论证
## 三、证据与案例
## 四、限定与反方
## 五、影响与建议
```

## 通用结构规则

- 上述二级标题的文案和顺序必须原样保留。
- 可在标准章节下增加三级标题，但不得用自拟二级标题取代模板章节。
- 次类型框架只用于主类型章节内的局部表达。

## JSON 渲染契约

模板只定义总结结构，不写入 WeKnora。生成结果使用以下字段：

```json
{
  "schemaVersion": 2,
  "videoType": "training",
  "classification": {
    "confidence": 0.91,
    "reason": "内容包含明确的学习目标、步骤和应用要求",
    "evidenceChunkIds": ["转写分块 ID"]
  },
  "sections": [
    {
      "id": "learning-goals-audience-prerequisites",
      "title": "一、学习目标、适用对象与前置知识",
      "blocks": [
        {
          "id": "block-1",
          "kind": "paragraph",
          "text": "可直接展示的纯文本",
          "evidenceChunkIds": ["转写分块 ID"]
        }
      ]
    }
  ]
}
```

- `block.kind` 只能是 `paragraph` 或 `bullet`。
- `block.text` 不得包含 Markdown 标题、列表符号、代码围栏或 HTML。
- 后端根据 `evidenceChunkIds` 回填 `evidence`，包括原文、起止时间和时间戳；LLM 不得自行填写出处正文。
- 每个展示 block 至少关联一个当前转写代次的证据分块。
- 培训模板中，原文无可靠依据的固定章节使用空数组 `"blocks": []`；空章节不创建占位 block。
