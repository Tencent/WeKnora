# Wiki 页面生成规范

## 通用规则

- 类型判断：**阅读 Wiki 页面** 获取本体分类标识 → 匹配下表类型 → 无法明确匹配时用最接近模板，页面底部标注"类型待确认"。
- 内容统一通过 **精读源文档** 提取；关系通过 **查询知识图谱** 获取 confirmed 关系；相邻概念通过 **搜索 Wiki** 交叉验证。
- 源文档未涉及的字段留空，不编造。
- 页面标题使用 Wiki 双链格式 `[[名称]]`。

## 实体类型

### person 人物

识别：页面主体描述一个具体人物的职业身份、经历或观点。

- `identity`：职业身份、所属机构和职位。示例：BAI Capital 合伙人
- `background`：教育背景、关键经历和转折点。示例：2011 年起实习，持续从事 VC 约 15 年
- `expertise`：擅长领域和关注方向。示例：早期投资、AI 应用、消费与实体体验
- `standpoint`：代表性观点或判断倾向。示例：投资非共识项目，重视创始人愿景而非壁垒

至少填充两项方可发布；standpoint 必须有原文支撑，不根据身份推测。

### organization 机构与组织

识别：页面主体描述公司、投资机构、研究团队或组织实体。

- `org_type`：机构类型。示例：投资机构 / 创业公司 / 研究机构
- `industry`：所在行业。示例：风险投资 / AI 硬件
- `stage`：发展阶段或规模。示例：合伙人级 / 早期团队
- `core_business`：核心业务或代表项目。示例：早期科技投资 / Context Machine
- `key_people`：关键人物，应可链接到 person 页面。示例：汪天凡 / 渊明

### product 产品

识别：页面主体描述一个具体产品、服务或可交付物。

- `product_type`：产品类别。示例：可穿戴硬件 / 线下社交服务
- `target_users`：目标用户。示例：关注上下文记录的用户 / 线下社交参与者
- `core_function`：核心功能。示例：全天候记录听、说、看和行为反馈
- `tech_basis`：技术基础。示例：AI 模型 + 硬件采集
- `differentiation`：差异化特点或竞争定位。示例：交互和价值观理解优于硬件采集本身

differentiation 必须有原文中明确的对比表述，不根据功能列表自行推断竞争定位。

### technology 技术

识别：页面主体描述一项技术、技术方向或技术范式。

- `tech_category`：技术分类。示例：人工智能 / 分布式账本
- `application_area`：应用领域。示例：投资研究、产品交互、基础设施
- `maturity`：发展阶段或成熟度。示例：基础设施热潮期 / 早期探索

maturity 判断必须引用源文档中的时间线索或市场描述，不根据发布日期推测。

### industry 行业

识别：页面主体描述一个行业、市场领域或赛道。

- `scope`：行业范围。示例：一级市场早期科技投资
- `stage`：发展阶段。示例：AI 加速期
- `key_trends`：当前关键趋势。示例：AI 原生组织、基础设施估值弹性、消费与实体被低估

key_trends 中每条趋势必须可回指源文档具体段落，不根据常识补齐。

### place 地点

识别：页面主体描述一个城市、地区、国家或场所，且与文字稿内容有明确关联。

- `place_type`：地点类型。示例：城市 / 地区 / 国家 / 场所
- `associated_activity`：关联活动或事件。示例：录制地点、市场区域、项目所在地

仅在该地点与文字稿内容有实质关联时创建页面，不为提到的每个地名都生成。

## 知识原子结构维度

### 方法论

适用条件：至少具有 input、steps、criteria 或 output 中的两项。

- `input`：前提或输入信息。示例：用户留存率下降的周度数据，含分群和渠道维度
- `steps`：操作步骤或行动序列。示例：1. 按渠道拆分留存曲线；2. 对比异常与正常渠道；3. 排查产品变更、运营活动和外部事件
- `criteria`：判断标准和取舍依据。示例：变更时间与留存拐点时间差不超过 3 天；排除无关联并发变更
- `output`：产出的结论或决策。示例：导致留存下降的具体变更项及回滚或修复方案
- `applicability`：适用条件和限制。示例：适用于单指标异常归因；不适用于多指标同时波动的系统性问题

steps 必须按源文档中的原始顺序排列，不重新编排或合并。

### 案例

适用条件：必须具有具体情境、参与对象和实际过程。

- `context`：背景和前提条件。示例：2024 Q3 某社交产品日活连续 6 周下滑，团队预算缩减
- `actors`：参与对象及其角色。示例：产品负责人（决策者）、增长团队（执行）、外部投放代理（供应商）
- `choices`：面临的选项和最终选择。示例：选项：砍品牌保效果 / 全量缩减；最终选择砍品牌投放
- `actions`：实际执行过程和关键动作。示例：1. 暂停品牌信息流广告；2. 节省预算转至效果广告；3. 两周后观察留存和 CAC
- `outcome`：结果和后续影响。示例：效果广告 CAC 上升 20%，日活止跌但品牌搜索量下降 40%
- `retrospective`：事后复盘判断。示例：品牌投放长期价值被低估，应优先重建

actors 角色标注必须来自源文档；outcome 无量化数据时标注"源文档未提供量化数据"。

### 概念

适用条件：概念回答"它是什么"。

- `definition`：定义或核心界定。示例：网络效应：产品价值随用户数量增加而增加的现象
- `components`：构成要素或内部结构。示例：用户基数、节点间连接密度、价值传导路径
- `mechanism`：运行机制或原理。示例：每新增一个用户为已有用户增加可连接节点，提升整体效用
- `distinction`：与相邻概念的关键区别。示例：与规模效应不同，网络效应价值增量来自连接关系而非单位成本下降

definition 必须使用源文档原始表述，不用通用百科定义替代；通过 **搜索 Wiki** 检索相邻概念页面填充 distinction。

### 洞察

适用条件：洞察回答"对此应当如何判断"。

- `claim`：核心判断或主张。示例：AI 基础设施估值存在泡沫，但应用层仍被低估
- `reasoning`：推导过程和依据。示例：基础设施投资额 3 年增长 10 倍但收入未同步；应用层 DAU 增速快但估值倍数低于基建
- `qualifications`：限定条件和适用范围。示例：仅适用于北美市场；不适用于有强政策保护的基建项目
- `implications`：推论、影响或行动建议。示例：应减少基建跟投，转向有明确收入模型的应用层项目

claim 必须忠实于说话人原始表述和确定程度；qualifications 未明确提及时标注"源文档未明确限定"。
