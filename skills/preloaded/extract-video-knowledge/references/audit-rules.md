# 知识提取审计规则

本文件定义候选去向、最终质量状态和完成门禁。类型门禁见 [type-frameworks.md](type-frameworks.md)，页面与关系结构见 [wiki-schema.md](wiki-schema.md)。

## 1. 审计顺序

```text
输入范围 → 章节覆盖 → 分类与原子性 → 类型门禁
→ 身份特征与冲突 → 证据贡献 → 正文一致性 → 最终状态 → 规范写入回读
```

前项失败时不能跳到后项；置信度和总分不能覆盖事实、证据、代次或类型错误。

## 2. 输入与覆盖

- 视频、整篇源文档、转写代次和证据全集唯一且一致，全部分块已按分页上限读完。
- 每个实质章节已映射候选或记录章节 ID 和排除原因。
- 定义、实践过程、方法、判断、限制、转折和未决问题均纳入检查。
- 旧代次和外部材料不提供本轮原文证据。

身份或代次冲突时停止 Wiki 覆盖。没有人工基准时只报告章节覆盖数量，不宣称召回率。

## 3. 候选去向

| 结果 | 条件 | 必须记录 |
|---|---|---|
| `publish_candidate` | 满足共同条件和类型门禁 | 唯一类型、核心内容、字段、对象证据和字段证据 |
| `merge` | 不能独立发布，但存在当前视频当前代次内的明确目标 | 目标对象、内容、证据和原因 |
| `repair` | 结构、分类或证据映射可能修复 | 问题、动作、次数和结果 |
| `review_required` | 对象边界、类型、范围或关键事实存在无法自动消除的冲突 | 判定依据、命中目标和冲突字段 |
| `reject` | 普通词、孤立提及、无证据、无独立价值或无合并目标 | 标题、证据和原因 |

自动修复最多 2 次。合并后重新审计目标对象，且不能引入跨类型字段或多个主命题。

## 4. 对象审计

### 4.1 分类与原子性

- 类型由对象回答的问题决定，且只使用五类合法值；实体子类型合法。
- `type` 与 `primary_type` 一致。
- 已按 [type-frameworks.md](type-frameworks.md) 第 8 节形成身份特征；类型装饰未进入标题，规范标题建议、别名建议和复合对象处理有记录。
- 可分别成立、取证和复用的命题已拆分；构成、方法步骤和同一判断的两个面保持完整。
- 标题或核心内容使用“+”“和”“与”等连接多个属性、条件或实现手段时，已执行维度独立性测试；仅为维度组合的候选必须 `merge` 到最近上位对象，不能作为独立概念或洞察发布。存在更高层判断时，洞察标题和核心判断表达结论，各维度分别进入推导依据。
- 标题含多个名词但未使用连接词时同样执行独立性测试；`AI Agent 第二大脑`一类并置标题不能绕过复合对象审计。
- 混合候选无法唯一分类时进入 `repair`，不按固定优先级发布。

### 4.2 身份与冲突

- 五类身份特征均覆盖 [type-frameworks.md](type-frameworks.md) 第 7 节要求的比较维度。
- Skill 没有把候选 ID、建议标题或建议 slug 当作规范身份，也没有按标题直接选择覆盖页面。
- 同名异义、类型或实体子类型冲突、多目标命中、适用范围冲突和关键事实冲突均记录判定依据与冲突字段，并进入 `review_required`。
- 写入工具超时、返回无合法结构或语义不确定时失败关闭，不退回字符相似度、关键词重合或标题相同直接合并。
- 每个候选都与同一规范页面锚点独立比较，不使用语义等价的传递推导。

### 4.3 类型门禁

逐对象执行 [type-frameworks.md](type-frameworks.md) 第 2 节，并记录通过或失败原因。

### 4.4 证据贡献与正文

- 每个对象恰有一组当前视频当前代次的 `evidence_contribution`，包含 1–3 个直接证据，时间范围有效。
- 每个非空结构字段都有对象证据子集，字段值能被对应证据直接支持。
- 页面标题、核心内容、结构字段、正文和证据表达同一对象。
- 引文忠于原文；概括没有扩大范围、语气、确定程度或因果关系。
- 空字段、占位语、模型旁白和无证据事实未进入输出。
- 来源字段符合 [wiki-schema.md](wiki-schema.md) 第 3 节，未互相代填；证据正文没有复制到 Wiki。

## 5. 最终质量状态

| 状态 | 条件 | 后续 |
|---|---|---|
| `passed` | 类型、原子性、必填字段、证据和正文一致性全部通过 | 可写可信 Wiki、正式关系、图谱和问答优先结果 |
| `conditional` | 通过部分可用，但仍有明确的非事实性缺口 | 仅展示通过部分并标记问题；不进图谱和优先问答 |
| `failed` | 身份、代次、事实、证据或核心类型门禁失败 | 不写可信对象页；保留失败记录或修复草稿 |
| `review_required` | 规范身份、对象边界或冲突无法自动确定 | 标记问题并等待修复；不得新建可见对象 |

`publish_candidate` 只是最终审计资格，不能直接改为 `passed`。关系失败只影响关系。

## 6. 关系与写入

- 正式关系属于八类契约，方向正确，且有当前代次证据、有效时间和足够置信度。
- 两端对象为 `passed`，目标规范对象 ID 和规范页面 ID 来自写入返回且真实可读；普通双链未升级为关系。
- 对象首次写入不引用未落地页面，第二次只补通过校验的关系和阅读关联。
- 所有规范页面和索引均按工具返回的 ID 与 slug 回读；候选身份没有继续流入下游，失败已标记问题。
- 每次提交均记录 `created`、`reused` 或 `review_required`、判定依据和冲突字段；`review_required` 后没有通过新 slug 绕过阻断。

## 7. 内容质量观察

审计可指出论据不足、弱因果、过度推广、偏差、方法不可复现、缺少限定或需外部核验，但不改写说话人的原始陈述。外部核验只作旁注，并记录来源、主张、结果和日期。

## 8. 完成门禁

一次运行只有同时满足以下条件才可报告完成：

1. 实质章节已覆盖或有排除原因；
2. 每个候选有唯一去向；
3. 每个拟落库对象有最终状态；
4. 每个 `passed` 候选恰有一组可回查的证据贡献；
5. 所有正式关系通过校验；
6. 所有规范页面和索引已按返回身份回读；
7. 每张写入页可追溯到生产任务、V2 Skill、`wiki_write_page` 工具调用和源文档；
8. 运行摘要中的数量、失败和降级来自实际记录；
9. 当前范围不存在语义等价但使用不同规范对象 ID 或规范页面 ID 的 `passed` 对象。
