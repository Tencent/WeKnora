# 统一知识本体

四种视频类型共用同一套知识对象，不按视频类型另建原子类型：

| 知识对象 | 保存位置 | 内容范围 |
|---|---|---|
| 实体 `entity` | `entities.jsonl` | 人物、机构或组织、产品、技术、行业、地点 |
| 方法论 `methodology` | `knowledge-atoms.jsonl` | 可复用框架、分析模型、判断标准、决策流程 |
| 案例 `case` | `knowledge-atoms.jsonl` | 具体事件、决策过程、行动、结果和复盘 |
| 概念 `concept` | `knowledge-atoms.jsonl` | 知识单元、术语、原理、抽象工具和指标 |
| 洞察 `insight` | `knowledge-atoms.jsonl` | 观点判断、趋势预测、价值主张和经验结论 |

每个知识原子只能选择 `methodology`、`case`、`concept`、`insight` 中的一个 `primary_type`。视频类型与知识类型彻底解耦：同一视频可以包含多种知识类型，同一知识类型可以出现在不同视频类型中。

## 实体类型与关键信息维度

不同实体类型关注不同的信息维度。提取时根据实体类型填充对应的 `key_attributes`，视频中未涉及的字段留空，不编造。所有字段值必须有证据支持。

### `person` 人物

| 字段 | 含义 | 示例 |
|---|---|---|
| `identity` | 职业身份、所属机构和职位 | BAI Capital 合伙人 |
| `background` | 教育背景、关键职业经历和转折点 | 2011 年起实习并持续从事 VC 约 15 年 |
| `expertise` | 擅长领域和关注方向 | 早期投资、AI 应用、消费与实体体验 |
| `standpoint` | 代表性观点或判断倾向 | 投资非共识项目，重视创始人愿景而非壁垒 |

### `organization` 机构与组织

| 字段 | 含义 | 示例 |
|---|---|---|
| `org_type` | 机构类型 | 投资机构 / 创业公司 / 研究机构 |
| `industry` | 所在行业 | 风险投资 / AI 硬件 |
| `stage` | 发展阶段或规模 | 合伙人级 / 早期团队 |
| `core_business` | 核心业务或代表性项目 | 早期科技投资 / Context Machine 产品 |
| `key_people` | 关键人物 | 汪天凡 / 渊明 |

### `product` 产品

| 字段 | 含义 | 示例 |
|---|---|---|
| `product_type` | 产品类别 | 可穿戴硬件 / 线下社交服务 |
| `target_users` | 目标用户 | 关注上下文记录的用户 / 线下社交参与者 |
| `core_function` | 核心功能 | 全天候记录听、说、看和行为反馈 |
| `tech_basis` | 技术基础 | AI 模型 + 硬件采集 |
| `differentiation` | 差异化特点或竞争定位 | 交互和价值观理解优于硬件采集本身 |

### `technology` 技术

| 字段 | 含义 | 示例 |
|---|---|---|
| `tech_category` | 技术分类 | 人工智能 / 分布式账本 |
| `application_area` | 应用领域 | 投资研究、产品交互、基础设施 |
| `maturity` | 发展阶段或成熟度 | 基础设施热潮期 / 早期探索 |

### `industry` 行业

| 字段 | 含义 | 示例 |
|---|---|---|
| `scope` | 行业范围 | 一级市场早期科技投资 |
| `stage` | 发展阶段 | AI 加速期 |
| `key_trends` | 当前关键趋势 | AI 原生组织、基础设施估值弹性、消费与实体被低估 |

### `place` 地点

| 字段 | 含义 | 示例 |
|---|---|---|
| `place_type` | 地点类型 | 城市 / 地区 / 国家 / 场所 |
| `associated_activity` | 关联活动或事件 | 录制地点、市场区域、项目所在地 |

## 方法论结构维度

方法论原子必须具有输入、步骤、判断标准或输出中的至少两项。提取时在 `method_structure` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `input` | 使用该方法论需要的前提或输入信息 | 用户留存率下降的周度数据，含分群和渠道维度 |
| `steps` | 操作步骤或行动序列 | 1. 按渠道拆分留存曲线；2. 对比异常渠道与正常渠道的差异；3. 逐一排查产品变更、运营活动和外部事件 |
| `criteria` | 判断标准和取舍依据 | 变更时间与留存拐点的时间差不超过 3 天；排除无关联的并发变更 |
| `output` | 方法论产出的结论或决策 | 导致留存下降的具体变更项及对应的回滚或修复方案 |
| `applicability` | 适用条件和限制 | 适用于单指标异常归因；不适用于多指标同时波动的系统性问题 |

## 案例结构维度

案例必须具有具体情境、参与对象和实际过程。提取时在 `case_structure` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `context` | 案例发生时的背景和前提条件 | 2024 年 Q3 某社交产品日活连续 6 周下滑，团队预算缩减 |
| `actors` | 参与对象及其角色 | 产品负责人（决策者）、增长团队（执行）、外部投放代理（供应商） |
| `choices` | 面临的选项和最终选择 | 选项：砍品牌投放保效果投放 / 全量缩减；最终选择砍品牌投放 |
| `actions` | 实际执行的过程和关键动作 | 1. 暂停品牌信息流广告；2. 将节省预算转至效果广告；3. 两周后观察留存和 CAC 变化 |
| `outcome` | 结果和后续影响 | 效果广告 CAC 上升 20%，整体日活止跌但品牌搜索量下降 40% |
| `retrospective` | 事后的复盘判断 | 品牌投放的长期价值被低估，应在预算恢复后优先重建 |

## 概念结构维度

概念回答"它是什么"。提取时在 `concept_structure` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `definition` | 概念的定义或核心界定 | 网络效应：产品价值随用户数量增加而增加的现象 |
| `components` | 构成要素或内部结构 | 用户基数、节点间连接密度、价值传导路径 |
| `mechanism` | 运行机制或原理 | 每新增一个用户，为所有已有用户增加可连接的节点，从而提升整体效用 |
| `distinction` | 与相邻概念的关键区别 | 与规模效应不同，网络效应的价值增量来自连接关系而非单位成本下降 |

## 洞察结构维度

洞察回答"对此应当如何判断"。提取时在 `insight_structure` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `claim` | 核心判断或主张 | 当前 AI 基础设施估值存在泡沫，但应用层仍被低估 |
| `reasoning` | 推导过程和依据 | 基础设施投资额 3 年增长 10 倍但收入未同步；应用层 DAU 增速快但估值倍数低于基建 |
| `qualifications` | 限定条件和适用范围 | 仅适用于北美市场；不适用于有强政策保护的基础设施项目 |
| `implications` | 推论、影响或行动建议 | 应减少基建跟投，转向有明确收入模型的应用层项目 |

## 类型边界判定规则

### 实体与概念

- OpenAI、BAI Capital、汪天凡、Looki → 实体
- Context、网络效应、非共识 → 概念
- 某个具体软件工具 → `product` 实体
- 一种抽象分析工具 → `concept`

判定标准：可以被稳定指认的具体对象归为实体；可独立理解和引用的抽象知识单元归为概念。人物与机构事实直接写入实体的 `key_attributes`，不创建 `person_fact` 等伪知识原子。

### 概念与方法论

- "三非理论包含非共识、非连续、非线性" → 概念
- "使用三非理论判断早期项目" → 方法论

判定标准：方法论必须具有输入、步骤、判断标准或输出中的至少两项。只描述"是什么"而不具备可操作结构的归为概念。

### 方法论与案例

- "早期公司应该考察竞争力而不是壁垒" → 方法论
- "投资 Looki 时如何判断团队和产品" → 案例

判定标准：案例必须具有具体情境、参与对象和实际过程。可重复使用的行动或判断结构归为方法论；在具体情境中发生的实践过程归为案例。

### 概念与洞察

- "智慧包含反馈、经验、反思和 Context" → 概念
- "智能会通胀，智慧仍然稀缺" → 洞察

判定标准：概念回答"它是什么"；洞察回答"对此应当如何判断"。

### 案例与洞察

一段案例可以产生洞察，但应拆成两个对象，用 `derived_from` 连接：

```text
Looki 投资过程
类型：case
        ↓ derived_from
AI 硬件的竞争力来自交互和团队能力
类型：insight
```

## 原子化测试

一个知识原子必须：

1. 只表达一个主要命题；
2. 脱离原段落仍可理解；
3. 能独立关联证据；
4. 只有一个主要类型；
5. 具有独立检索或复用价值。

能够独立成立的组合命题应拆分。不要把完整方法论拆成互不关联的步骤：步骤可作为方法论的一部分，但必须通过 `part_of` 归属于同一个复合方法论。每个知识原子和每个实体必须生成独立 Wiki 文件，文件粒度规则见 [wiki-schema.md](wiki-schema.md)。

## 命题拆分规则

原子化测试第 1 条"只表达一个主要命题"是硬性约束。当发现一个原子包含多个独立命题时，必须拆分为多个原子，并通过关系连接。

### 多命题识别信号

| 类型 | 信号 | 示例 |
|---|---|---|
| 概念 | `definition` 出现"A 是…；B 是…"并列结构；`title` 含"与""和""vs"连接两个独立概念 | "Agent Native 与 Prompt Flow 的范式之争" → 拆为"Agent Native"和"Prompt Flow" |
| 洞察 | `claim` 包含两个不同主张或判断；`title` 含"与""和"连接两个独立结论 | "智能会通胀，智慧仍然稀缺" 不拆（同一命题的两个面）；"模型才是 agent，且 prompt flow 会消亡" → 拆为两条洞察 |
| 方法论 | `steps` 包含两套不相关的操作序列；`title` 含"与""和"连接两种不同方法论 | "上下文压缩与 Agent 接力策略"不拆（同一方法论的两种策略）；"用户留存归因与渠道优化" → 拆为两个方法论 |
| 案例 | `actors` 或 `actions` 描述两个不相关的事件 | "投资 Looki 与投资 Context Machine" → 拆为两个案例 |

### 拆分判断原则

- 两个命题共享同一结构字段且互为定义的一部分时，不拆分（如概念的 `components` 列出多个构成要素）
- 两个命题能各自独立成立、各自关联证据、各自被独立检索时，必须拆分
- 两个命题互为对立面、互为因果或互为补充时，拆分后用关系连接

### 拆分后的关系连接

拆分后的关系类型定义见 [relation-rules.md](../../build-video-knowledge-graph/references/relation-rules.md)，以下为拆分场景的常用映射：

| 命题关系 | 关系类型 | 示例 |
|---|---|---|
| 对立 / 竞争 | `contradicts` | Agent Native `contradicts` Prompt Flow |
| 互补 / 协同 | `complements` | More Context Less Control `complements` Agent Native |
| 因果 / 解释 | `explains` | 模型才是 Agent `explains` Agent Native |
| 实例 | `example_of` | Claude Code `example_of` Agent Native |
| 子命题 | `part_of` | 某步骤 `part_of` 复合方法论 |
