# 五类知识对象规则

本文件是五类语义、字段和最低发布条件的唯一来源。

## 1. 共同条件

独立对象必须具备稳定标题、一句话核心内容、唯一顶层类型、独立复用价值、当前代次内 1–3 个最小充分证据，以及覆盖每个非空结构字段的字段证据。

## 2. 类型与门禁

先判断对象回答的问题，再校验必填组合；不按命中字段数量分类。可选字段不能替代必填项。

| 类型 | 回答的问题 | 必填组合 | 可选字段 |
|---|---|---|---|
| 实体 `entity` | 谁或什么具体对象？ | 稳定名称 + 合法子类型 + 至少 1 项有证据且能说明身份、角色或用途的属性 | 当前子类型其余属性、别名 |
| 概念 `concept` | 它是什么、为何如此？ | `definition` + `components` / `mechanism` / `distinction` 至少 1 项 | `examples`、`scope` 及其余概念字段 |
| 方法论 `methodology` | 如何重复执行或判断？ | `steps` + `input` / `criteria` / `output` / `applicability` 至少 1 项 | `risks` 及其余方法字段 |
| 案例 `case` | 具体情境中实际发生了什么？ | `context` + `actions` + `outcome` / `retrospective` 至少 1 项 | `actors`、`choices` 及其余案例字段 |
| 洞察 `insight` | 基于哪些依据应当如何判断？ | `claim` + `reasoning` | `qualifications`、`implications` |

## 3. 字段与展示顺序

正文按以下顺序展示有值且有证据的字段。英文键只用于结构化数据。

| 类型或子类型 | 字段顺序 |
|---|---|
| `person` | `identity` 职业身份 → `background` 教育背景与经历 → `expertise` 擅长领域 → `standpoint` 代表性观点 |
| `organization` | `org_type` 机构类型 → `industry` 所在行业 → `stage` 发展阶段 → `core_business` 核心业务 → `key_people` 关键人物 |
| `product` | `product_type` 产品类别 → `target_users` 目标用户 → `core_function` 核心功能 → `tech_basis` 技术基础 → `differentiation` 差异化特点 |
| `technology` | `tech_category` 技术分类 → `application_area` 应用领域 → `maturity` 发展阶段 |
| `industry` | `scope` 行业范围 → `stage` 发展阶段 → `key_trends` 关键趋势 |
| `place` | `place_type` 地点类型 → `associated_activity` 关联活动 |
| `concept` | `definition` 定义 → `components` 构成要素 → `mechanism` 运行机制 → `distinction` 相邻区别 → `examples` 示例 → `scope` 适用边界 |
| `methodology` | `input` 输入 → `steps` 步骤 → `criteria` 判断标准 → `output` 输出 → `applicability` 适用条件与限制 → `risks` 风险 |
| `case` | `context` 背景 → `actors` 参与对象 → `choices` 选择 → `actions` 行动 → `outcome` 结果 → `retrospective` 复盘判断 |
| `insight` | `claim` 核心判断 → `reasoning` 推导依据 → `qualifications` 限定条件 → `implications` 影响建议 |

未列出的键是跨类型字段。相关对象通过 [wiki-schema.md](wiki-schema.md) 的关系或阅读关联表达，不保存为名称列表。

## 4. 实体子类型

实体必须可稳定指认且对理解视频有实际作用。名称、别名、出现次数和类别标签不算有效属性。

| `entity_sub_type` | 对象 | 典型有效属性 |
|---|---|---|
| `person` | 人物 | 身份、经历、擅长领域、观点倾向 |
| `organization` | 机构或组织 | 类型、行业、业务、阶段、关键人物 |
| `product` | 软件、硬件、服务或项目产品 | 类别、用户、功能、技术、差异化 |
| `technology` | 可指认的技术体系或技术对象 | 分类、应用领域、成熟度 |
| `industry` | 有明确范围的行业或市场 | 范围、阶段、趋势 |
| `place` | 国家、地区、城市或场所 | 地点类型、关联活动 |

同视频内可确认的全称、简称和别名合并；身份无法确认一致时分开。可独立复用的人物观点生成洞察并用 `involves` 关联人物，实体页不复制洞察正文。

## 5. 类型边界

| 边界 | 判定 |
|---|---|
| 实体 / 概念 | 可稳定指认的具体对象归实体；抽象知识单元归概念 |
| 概念 / 方法论 | 定义和原理归概念；包含至少两个有顺序或依赖关系的步骤才归方法论 |
| 方法论 / 案例 | 可跨情境重复的流程归方法论；具体情境中已发生的过程归案例 |
| 概念 / 洞察 | 定义和解释归概念；有依据的判断归洞察 |
| 案例 / 洞察 | 事件过程归案例；由事件支持的独立判断归洞察，拆分后以 `supports` 连接 |

补充规则：

- 普通词义、泛称、代词、无法消歧简称不独立发布。
- 方法论步骤少于两个，或只有目标、原则、建议时，重分类或并入已有对象。
- 假设场景、未来计划和泛化举例不作为案例；进行中事件不能推测结果。
- 洞察保留原文的确定程度、范围和时间背景，不能把相关性改写成因果。
- 同一对象的构成、步骤和同一判断的两个面保持完整；可分别成立、取证和复用的命题拆分。
- 并列出现的属性、条件或实现手段先做维度独立性测试：若 A 可以在没有 B 时成立，B 也可以在没有 A 时成立，则二者是独立维度，不得把“A+B”“A 和 B”或“A 与 B”本身命名为概念或洞察。
- 独立维度应保留在最近上位对象的属性、构成、判断标准或推导依据中。原文确实基于这些维度提出更高层判断时，可以生成洞察，但标题和核心判断必须表达该结论，不能直接拼接维度名称。

无法得到唯一类型时进入 [audit-rules.md](audit-rules.md) 定义的 `repair`，不能按固定优先级强行归类。

## 6. 标题与核心内容

- `title`、页面标题和唯一 H1 一致；实体 `canonical_name` 同值。
- 标题直接使用稳定对象名称，不使用模板标题，也不拼接多个独立对象。
- `（实体）`、`（概念）`、`（方法论）`、`（案例）`、`（洞察）`及其英文形式只描述类型，必须写入类型字段，禁止进入标题。例：`Codex（实体）`的规范标题是`Codex`。
- 视频、章节、产品或应用场景只是来源上下文时，禁止拼到对象名前。`AI Agent 第二大脑`若正文仍在定义“第二大脑”，应以`第二大脑`为规范标题，并把 AI Agent 写入构成、机制或关系。
- 标题含两个可独立指认、取证和复用的对象时必须拆分。若正文同时定义`AI Agent`和`第二大脑`，分别生成对象并建立正式关系；不得用拼接标题生成第三个对象。
- 同义改写不能仅按字面合并。`个人知识库五关标准`与`个人知识库五大条件`只有在具体条件、适用范围和判断机制基本一致时才共享一个对象；否则保持独立。
- 规范标题优先使用已有对象标题；没有已有对象时，选择最短且不丢失消歧信息的稳定名称，其他等价表述进入`aliases`。
- `core_content` 直接回答该类型的业务问题，不写页面自述。

## 7. 身份特征与等价边界

Skill 为每个候选提供可比较的身份特征，不输出最终身份判定。标题、别名、关键词和字符相似度只用于候选召回，不能单独证明同义。

| 类型 | 身份判定必须比较 | 允许差异 |
|---|---|---|
| 实体 | 是否指向同一个人物、组织、产品、技术、行业或地点 | 别名、简称、属性详略、表述和证据来源 |
| 概念 | 定义、适用范围、核心构成或机制 | 表述方式、示例和解释详略 |
| 方法论 | 目标、输入、关键步骤或判断逻辑、输出 | 步骤措辞、补充注意事项和案例 |
| 案例 | 时间背景、参与对象、事件过程 | 叙述角度、复盘详略和补充结果 |
| 洞察 | 核心判断、方向、适用条件和限定 | 推导表达、证据来源和建议详略 |

类型、实体子类型、适用范围或关键事实互相冲突时，必须把冲突字段写入候选审计记录。语义等价不是传递关系：每个候选都要由服务端与同一个规范页面锚点比较，不得因 A 与 B、B 与 C 分别相似而推导 A 与 C 同义。

## 8. 候选处理顺序

1. 去除标题中的类型装饰和纯来源上下文，但保留用于消歧的行业、版本或专名。
2. 对复合标题执行独立性测试：两个部分能分别成立、取证和复用时拆分；只表达一个对象的场景化说法时归一为该对象。
3. 确定唯一建议类型，输出该类型要求的身份特征、规范标题建议和别名建议。
4. 类型、范围、关键事实或对象边界不确定时输出 `review_required` 和冲突字段，不提交可见对象。
5. 通过写入工具提交候选；工具返回的规范对象 ID、规范 Wiki 页面 ID、规范标题和 slug 是关系、二次写入和视频索引的唯一身份依据。
