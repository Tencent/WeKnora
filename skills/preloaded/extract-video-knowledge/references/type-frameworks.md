# 统一知识本体

本文件是提取、命名和前端结构展示的规则参考，必须保留。它不定义本地产物保存位置。
所有实体、方法论、案例、概念和洞察都以独立的 WeKnora Wiki 页面持久化；产物不得写入本地文件。

四种视频类型共用同一套知识对象，不按视频类型另建原子类型：

| 知识对象 | 持久化方式 | 内容范围 |
|---|---|---|
| 实体 `entity` | WeKnora Wiki 独立页面，`primary_type: entity`，用 `entity_sub_type` 细分 | 人物、机构或组织、产品、技术、行业、地点 |
| 方法论 `methodology` | WeKnora Wiki 独立页面，`primary_type: methodology` | 可复用框架、分析模型、判断标准、决策流程 |
| 案例 `case` | WeKnora Wiki 独立页面，`primary_type: case` | 具体事件、决策过程、行动、结果和复盘 |
| 概念 `concept` | WeKnora Wiki 独立页面，`primary_type: concept` | 知识单元、术语、原理、抽象工具和指标 |
| 洞察 `insight` | WeKnora Wiki 独立页面，`primary_type: insight` | 观点判断、趋势预测、价值主张和经验结论 |

每个知识原子只能选择 `methodology`、`case`、`concept`、`insight` 中的一个 `primary_type`；实体的 `primary_type` 固定为 `entity`，并必须填写 `entity_sub_type`。视频类型与知识类型彻底解耦：同一视频可以包含多种知识类型，同一知识类型可以出现在不同视频类型中。

## 命名与标题

- `title` 是页面一级标题（唯一的 H1），必须直接使用抽取对象的稳定名称：实体名称、方法论名称、概念名称、案例名称或洞察名称。
- `title` 必须与正文 H1 和 Wiki 页面标题一致；实体同时将同一名称写入 `canonical_name`。禁止使用“知识条目”“实体详情”“某某方法介绍”等模板标题。
- 名称应短、可检索、能脱离视频上下文独立理解。多个独立命题不得拼成一个标题，拆分后分别命名并建立关系。

## `information_nature` 知识标签

`information_nature` 是面向用户的知识性质标签，不是自由发挥的摘要。实体使用“人物 / 机构 / 产品 / 技术 / 行业 / 地点”，知识原子使用“方法论 / 案例 / 概念 / 洞察”；标签必须与 `primary_type` 和 `entity_sub_type` 一致。它需要同时写入后端字段和正文的“信息性质”字段，前端以中文标签展示。

## 结构维度展示契约

正文的“结构维度”必须由 `primary_type`（实体再看 `entity_sub_type`）驱动，只展示对应章节表中实际有值的字段，并按表中顺序使用中文标签。字段名只留在 frontmatter 的 `structure_fields`，不把英文键名直接展示给用户。

| `primary_type` / `entity_sub_type` | 正文允许展示的中文子字段 |
|---|---|
| `person` | 职业身份、教育背景与经历、擅长领域、代表性观点 |
| `organization` | 机构类型、所在行业、发展阶段、核心业务、关键人物 |
| `product` | 产品类别、目标用户、核心功能、技术基础、差异化特点 |
| `technology` | 技术分类、应用领域、发展阶段 |
| `industry` | 行业范围、发展阶段、关键趋势 |
| `place` | 地点类型、关联活动 |
| `methodology` | 输入、步骤、判断标准、输出、适用条件 |
| `case` | 背景、参与对象、选择、行动、结果、复盘判断 |
| `concept` | 定义、构成要素、运行机制、相邻区别 |
| `insight` | 核心判断、推导依据、限定条件、影响建议 |

未出现在对应行的字段即使在原文中出现，也必须并入核心内容或证据，不得借用其他类型的结构字段。实体页面按 `entity_sub_type` 选择前六行之一；知识原子页面按四种原子类型选择后四行之一。

## 方法论结构维度

方法论原子必须具有输入、步骤、判断标准或输出中的至少两项。提取时在统一的 `structure_fields` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `input` | 使用该方法论需要的前提或输入信息 | 用户留存率下降的周度数据，含分群和渠道维度 |
| `steps` | 操作步骤或行动序列 | 1. 按渠道拆分留存曲线；2. 对比异常渠道与正常渠道的差异；3. 逐一排查产品变更、运营活动和外部事件 |
| `criteria` | 判断标准和取舍依据 | 变更时间与留存拐点的时间差不超过 3 天；排除无关联的并发变更 |
| `output` | 方法论产出的结论或决策 | 导致留存下降的具体变更项及对应的回滚或修复方案 |
| `applicability` | 适用条件和限制 | 适用于单指标异常归因；不适用于多指标同时波动的系统性问题 |

## 案例结构维度

案例必须具有具体情境、参与对象和实际过程。提取时在统一的 `structure_fields` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `context` | 案例发生时的背景和前提条件 | 2024 年 Q3 某社交产品日活连续 6 周下滑，团队预算缩减 |
| `actors` | 参与对象及其角色 | 产品负责人（决策者）、增长团队（执行）、外部投放代理（供应商） |
| `choices` | 面临的选项和最终选择 | 选项：砍品牌投放保效果投放 / 全量缩减；最终选择砍品牌投放 |
| `actions` | 实际执行的过程和关键动作 | 1. 暂停品牌信息流广告；2. 将节省预算转至效果广告；3. 两周后观察留存和 CAC 变化 |
| `outcome` | 结果和后续影响 | 效果广告 CAC 上升 20%，整体日活止跌但品牌搜索量下降 40% |
| `retrospective` | 事后的复盘判断 | 品牌投放的长期价值被低估，应在预算恢复后优先重建 |

## 概念结构维度

概念回答"它是什么"，但不是普通词语释义。可发布为概念的对象必须是视频中可复用、可讨论、可与其他知识建立关系的知识单元；只解释一个字、一个普通词或一处修辞表达的，不生成独立概念页。提取时在 `structure_fields` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `definition` | 概念的定义或核心界定 | 网络效应：产品价值随用户数量增加而增加的现象 |
| `components` | 构成要素或内部结构 | 用户基数、节点间连接密度、价值传导路径 |
| `mechanism` | 运行机制或原理 | 每新增一个用户，为所有已有用户增加可连接的节点，从而提升整体效用 |
| `distinction` | 与相邻概念的关键区别 | 与规模效应不同，网络效应的价值增量来自连接关系而非单位成本下降 |

## 洞察结构维度

洞察回答"对此应当如何判断"。提取时在统一的 `structure_fields` 中填充以下维度，视频中未涉及的字段留空，不编造。

| 字段 | 含义 | 示例 |
|---|---|---|
| `claim` | 核心判断或主张 | 当前 AI 基础设施估值存在泡沫，但应用层仍被低估 |
| `reasoning` | 推导过程和依据 | 基础设施投资额 3 年增长 10 倍但收入未同步；应用层 DAU 增速快但估值倍数低于基建 |
| `qualifications` | 限定条件和适用范围 | 仅适用于北美市场；不适用于有强政策保护的基础设施项目 |
| `implications` | 推论、影响或行动建议 | 应减少基建跟投，转向有明确收入模型的应用层项目 |

## 类型边界判定规则

### 实体与概念

- OpenAI、BAI Capital、汪天凡、Looki → 实体
- Context、网络效应、非共识 → 概念
- 某个具体软件工具 → `product` 实体
- 一种抽象分析工具 → `concept`

判定标准：可以被稳定指认的具体对象归为实体；可独立理解和引用的抽象知识单元归为概念。人物与机构事实直接写入实体的关键信息维度，不创建 `person_fact` 等伪知识原子。

### 概念与普通词义

- "网络效应"、"Agent Empathy"、"渐进式披露" → 概念
- "实"、"知道"、"实践含义"中的单字或普通词义解释 → 不生成概念页

判定标准：概念必须同时满足三项：有稳定命名；有超出原句的复用价值；至少能填充 `definition` 加 `components` / `mechanism` / `distinction` 中的一项。只有一句词义解释、标题中的拆字、正文双链显示文本、口头解释中的普通词，不具备产品知识图谱节点资格。需要保留时，写入所属概念、方法论或洞察的结构字段与正文，不单独建页。

### 概念与方法论

- "三非理论包含非共识、非连续、非线性" → 概念
- "使用三非理论判断早期项目" → 方法论

判定标准：方法论必须具有输入、步骤、判断标准或输出中的至少两项。只描述"是什么"而不具备可操作结构的归为概念。

### 方法论与案例

- "早期公司应该考察竞争力而不是壁垒" → 方法论
- "投资 Looki 时如何判断团队和产品" → 案例

判定标准：案例必须具有具体情境、参与对象和实际过程。可重复使用的行动或判断结构归为方法论；在具体情境中发生的实践过程归为案例。

### 概念与洞察

- "智慧包含反馈、经验、反思和 Context" → 概念
- "智能会通胀，智慧仍然稀缺" → 洞察

判定标准：概念回答"它是什么"；洞察回答"对此应当如何判断"。

### 案例与洞察

一段案例可以产生洞察，但应拆成两个对象，用 `derived_from` 连接：

```text
Looki 投资过程
类型：case
        ↓ derived_from
AI 硬件的竞争力来自交互和团队能力
类型：insight
```

## 原子化测试

一个知识原子必须：

1. 只表达一个主要命题；
2. 脱离原段落仍可理解；
3. 能独立关联证据；
4. 只有一个主要类型；
5. 具有独立检索或复用价值。

能够独立成立的组合命题应拆分。不要把完整方法论拆成互不关联的步骤：步骤可作为方法论的一部分，但必须通过 `part_of` 归属于同一个复合方法论。每个知识原子和每个实体必须生成独立 Wiki 文件，文件粒度规则见 [wiki-schema.md](wiki-schema.md)。

### 最小粒度闸门

生成独立页面前必须先通过最小粒度闸门：

| 闸门 | 发布为独立对象 | 合并进上级对象 |
|---|---|---|
| 命名 | 视频中以稳定术语、方法、案例或判断反复出现 | 只是普通词、单字词、显示文本或临时说法 |
| 信息量 | 能支持至少两个结构字段 | 只能写一句定义或一句原文转述 |
| 复用 | 用户可能单独搜索、引用或比较 | 只能依附在另一对象里才有意义 |
| 关系 | 能与其他对象形成可解释的强关系 | 只是在同一句或同一段落中相邻出现 |

未通过闸门时，把内容并入最近的上级概念、方法论、案例或洞察，并在该对象的 `structure_fields` 或 `core_content` 中保留原文意思。

## 核心内容规则

`core_content` 必须是基于原文意思的定义、判断或概括，直接回答“这个对象是什么 / 这个判断是什么 / 这个方法如何用 / 这个案例发生了什么”。避免页面自述、模板腔和空泛概括。

| 不合格 | 合格 |
|---|---|
| 本页定义“实”这一概念，指…… | “实”在原文中只是对“知道其内容”的口头解释，不应独立成概念；应并入相关认知概念。 |
| 本页介绍某方法论。 | 该方法通过先界定输入、再分步验证、最后输出判断来降低决策误差。 |
| 这是一个关于 AI 的概念。 | AI 智能体是能够在给定上下文和工具条件下自主推进任务的系统。 |

## 命题拆分规则

原子化测试第 1 条"只表达一个主要命题"是硬性约束。当发现一个原子包含多个独立命题时，必须拆分为多个原子，并通过关系连接。

### 多命题识别信号

| 类型 | 信号 | 示例 |
|---|---|---|
| 概念 | `definition` 出现"A 是…；B 是…"并列结构；`title` 含"与""和""vs"连接两个独立概念 | "Agent Native 与 Prompt Flow 的范式之争" → 拆为"Agent Native"和"Prompt Flow" |
| 洞察 | `claim` 包含两个不同主张或判断；`title` 含"与""和"连接两个独立结论 | "智能会通胀，智慧仍然稀缺" 不拆（同一命题的两个面）；"模型才是 agent，且 prompt flow 会消亡" → 拆为两条洞察 |
| 方法论 | `steps` 包含两套不相关的操作序列；`title` 含"与""和"连接两种不同方法论 | "上下文压缩与 Agent 接力策略"不拆（同一方法论的两种策略）；"用户留存归因与渠道优化" → 拆为两个方法论 |
| 案例 | `actors` 或 `actions` 描述两个不相关的事件 | "投资 Looki 与投资 Context Machine" → 拆为两个案例 |

### 拆分判断原则

- 两个命题共享同一结构字段且互为定义的一部分时，不拆分（如概念的 `components` 列出多个构成要素）
- 两个命题能各自独立成立、各自关联证据、各自被独立检索时，必须拆分
- 两个命题互为对立面、互为因果或互为补充时，拆分后用关系连接

### 拆分后的关系连接

以下为拆分场景的常用关系映射，也是本 Skill 的关系类型参考：

| 命题关系 | 关系类型 | 示例 |
|---|---|---|
| 对立 / 竞争 | `contradicts` | Agent Native `contradicts` Prompt Flow |
| 互补 / 协同 | `complements` | More Context Less Control `complements` Agent Native |
| 因果 / 解释 | `explains` | 模型才是 Agent `explains` Agent Native |
| 实例 | `example_of` | Claude Code `example_of` Agent Native |
| 子命题 | `part_of` | 某步骤 `part_of` 复合方法论 |

上述关系可连接任意知识原子与实体；目标不是按类型限制，而是按命题语义、证据和目标 Wiki 页面是否真实可读来判断。
