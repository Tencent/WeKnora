# 长期记忆与任务经验

用户记忆、执行经验、整理和召回共用一条生命周期。经验用于复用经过验证的操作步骤、失败原因和修正方法，实际提取质量需使用生产模型和代表性任务评估。

## 实现原则

- 从会话中的用户消息、助手报告、工具调用与执行结果提取经验，保留可核对的过程证据。
- 记录适用范围、失败与修正、验证结果和不确定性；没有可复用内容时不保存经验。
- 异步提取后按需整理，通过短索引、完整条目和详细证据逐步读取。
- 使用统一的文本读取和搜索入口，并按数据来源检查访问范围。
- 使用数据库和受控虚拟资源保存记忆，支持去重、人工维护保护及失败恢复。

## 统一写入

完成的回合进入原有 `MemoryExtract` 队列。一次提取请求同时输出普通记忆、任务总结和 `experience`，没有并行的第二套经验提取任务。

- 普通画像和偏好只从新增用户消息提取。工具内容不能成为用户偏好或授权来源。
- 经验从已完成助手消息的 `AgentSteps` 获取实际执行名称、参数、成功/失败、错误和输出；最终回答标为助手报告。
- Shell 的非零退出码和被终止状态是失败，即使工具传输本身成功。
- 跨回合提供有限的先前操作作为背景，但新经验必须引用至少一条新证据。
- 模型仅引用服务端编号；持久化的会话、消息、调用 ID 和 Agent 范围由服务端解析，不能由模型伪造。
- 经验正文最多 8000 字符，保留适用条件、失败路径、修正、验证方法和不确定性。无法验证的结果进入 `pending`，确认后使用。
- 凭证字段和常见敏感信息在提取、保存前脱敏。隐藏推理、二进制和仅供模型使用的大字段不进入经验输入。
- 手动编辑、明确记住的条目不会被自动提取或整理改写；删除、拒绝通过墓碑阻止重建。

每个会话保存 `(created_at, id)` 游标。慢回合不会被另一个会话的时间戳跳过；相同时间戳和分页也不丢消息。数据库租约阻止同一用户的并发提取；模型/解析失败不消费游标，失败时重入队。已领取的会话状态与游标一同持久化，worker 异常退出后重试可恢复整批会话；租约竞争会延后重试至租约到期，避免提前耗尽重试次数。停用记忆的回合保存退出标记，后续启用回合不能通过扫描历史重新学习它。

整理仍在同一后台流程中，按需执行，不是另一个竞争提取器。经验只有 Agent、适用范围、结果一致时才能归并，并保留证据与步骤。普通记忆仍兼容原管理 API。

## 召回与读取

1. 少量稳定画像与偏好进入常驻上下文。
2. 对全部有效候选进行关键词匹配，并与可选向量结果融合；最后才应用输出预算。向量模型不可用时退回关键词匹配，同一次召回复用查询向量。
3. 经验按完整正文、主题、工具名和适用条件匹配，但自动召回只注入最多 3 条短索引（1800 字符预算），不提前展开全部步骤。
4. Agent 可调用 `grep(path="memory://", pattern="report_query|invalid date")` 搜索完整有效条目，然后 `read` 命中的路径。搜索不依赖初始问题，也不受自动召回的条数限制。
5. `memory://MEMORY.md` 是完整索引；`memory://items/<id>.md` 是完整条目；`memory://evidence/<id>.md` 是任务总结及有界执行证据。

所有入口都检查空间、用户、Agent 开关。经验还绑定原 Agent 与其租户。过期、归档、待确认、已删除条目不会从文件读取或搜索旁路重新进入模型。管理页面仍可查看用户自己来自各 Agent 的记录和源会话。编辑或确认条目后立即尝试重建向量；模型不可用时仍保留词法召回，并由后续维护补齐。读取证据时，缺失或暂时不可用的源消息会明确标记，其余证据继续返回。

原来较早候选在排序前被截掉、只匹配短索引导致正文关键词失配、空结果回退到陈旧缓存等问题已修正。召回追踪分别记录普通记忆与经验的候选、关键词/向量命中和排序模式。

## 工具边界

| 操作 | 本次入口 | 处理方式 |
| --- | --- | --- |
| 文件、技能、网页、记忆、结果快照读取 | `read` | 共用分页；按来源独立检查访问范围 |
| 上述文本资源的正则/字面搜索 | `grep` | RE2、命中片段、路径与行号；支持续查 |
| 知识库语义检索 | `knowledge_search` | 保留召回、重排和来源引用语义 |
| 知识库关键词检索 | `grep_chunks` | 保留数据库正则、标签范围、FAQ 与文档引用 |
| 知识库深读、元数据 | `list_knowledge_chunks`、`get_document_info` | 保留分块分页、FAQ 回答和批量元数据 |
| Wiki 查找、读取、源文档 | 现有 Wiki 工具 | 保留跨知识库路由、同名消歧和来源范围 |
| 图谱查询 | `query_knowledge_graph` | 保留节点、边和关系查询 |
| 写入与修改 | 现有独立操作 | 不与只读入口合并 |

`read_file` 是历史兼容名称，新工具定义只提供 `read`。`search_memory` 不再注册，旧调用收到迁移指引。未把 KB/Wiki/Graph 硬改成文本文件：后续若合并，必须同时迁移 cN/dN/bN 引用编解码、FAQ、标签/共享范围和分页协议；不能仅套名称分发器。本次统一它们的大结果处理，保持原查询能力和权限。

## 长结果

- 已有 `web://` 或 `output://` 补读地址在通用截断时保留；批量网页的完整页地址仍保存在各结果中。
- `read` 按行分页；超长单行可用 `next_line_offset` 继续读取，UTF-8 不切坏，适用于各文本来源。
- `grep` 默认返回 50 条、最多 200 条命中，可附最多 3 行上下文；返回 `next_offset`。扫描限制、不可读文件和二进制会明确报告，不把不完整扫描当作没有结果。
- 注册表在截断大文本或大结构化结果之前，将原始结果保存成 `output://` 资源。模型侧不能再次从 `Data` 展开超预算内容。
- Shell 在自己的 stdout/stderr 截断之前保存捕获的流；Wiki 页面也在正文裁剪之前保存已授权解析到的页面。
- 快照复用已有文件存储和资源绑定，归属原助手消息。读取要求同租户、调用者、会话及执行配置；消息/会话删除后不可读。切换知识库或 Agent 配置后应重新检索，不能用旧快照扩大范围。
- 未配置存储、保存失败或超过 8 MiB 上限时，操作本身的成功/失败保持不变，并明确告知无法补读；冗长 Shell 命令可预先重定向到工作区日志。
- Wiki 快照按完整页面控制在存储上限内；未包含的页面会标记为部分结果，并提示单独读取。
- 已被上游截断的流无法恢复。经验提取只使用持久化的可见证据；长回合最多选择 24 条详细观察，优先初始/最后操作及中间失败、紧随其后的修正，并提供有限前文。被省略内容明确标记，不能作为成功依据。

## 迁移与验证

PostgreSQL：`000092_memory_experience`；SQLite：`000014_memory_experience`。增加经验元数据、会话进度和租约列，原记忆不删改。首次新版扫描会为待处理会话建立独立进度；已有条目的去重、人工保护和墓碑继续生效。回滚会删除新增经验及其向量，保留普通条目。

回归覆盖：单队列联合提取、完整正文匹配后输出短索引、旧条目可检索、跨用户/租户/Agent 隔离、关闭/删除、同时间戳分页、未完成回合、多轮证据、伪造证据拒绝、租约、手动条目保护、超长行续读、搜索分页、保存失败、Shell 中间输出补查、结果快照授权和模型结果预算。SQLite 升降级另有脚本验证。

这些检查覆盖实现约束。生产模型的提取质量评测和真实 PostgreSQL 升降级验证尚未执行。
