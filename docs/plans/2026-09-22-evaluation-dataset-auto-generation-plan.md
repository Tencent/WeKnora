# Evaluation Dataset Studio 自动创建评测数据集开发计划

## 1. 规划结论

- 目标：把评测数据集建设从“人工逐条编写”改为“语料驱动的 AI 候选生成 + 人工审核”。
- 当前优先级：先基于 Studio 已维护的本地语料生成问题、标准答案和答案要点，不依赖生产 WeKnora API。
- 输出兼容性：审核通过的数据继续写入现有 `Passage`、`Question` 与相关语料关系，最终仍导出严格的 WeKnora 五 Parquet ZIP。
- 安全边界：自动生成内容默认进入候选区或草稿状态，不允许未经审核直接进入正式发布数据集。
- 成本原则：默认每个语料生成 1 道题、低并发、单次硬预算、结果缓存；二次 LLM 评分默认关闭。

### P0 实施状态（2026-09-22）

- [x] A0：独立 OpenAI-compatible 模型配置、本机密钥保存和连接测试。
- [x] A1：选择语料并异步生成结构化候选，黄金语料由后端绑定。
- [x] A2：字段、长度、证据引用、重复和近似重复的确定性校验。
- [x] A3：候选查看、编辑后批准、批量批准/拒绝并写入正式问题。
- [x] A4：任务 token 上限、费用估算、单次重试、取消、进度和缓存。
- [x] A5：mock 模型自动化测试、使用文档和本地界面联调。

实现采用逐条语料、并发数固定为 1 的成本优先策略；P0 暂不开放并发配置。后续源文档导入与自动切片仍属于 P1。

### 后续主线调整（2026-09-23）

P0 自动生成已经完成，下一阶段先实施[配置中心与知识库分块导入开发计划](./2026-09-23-evaluation-dataset-source-and-config-center-plan.md)：集中管理生成模型和 WeKnora 环境，把 WeKnora 已解析分块导入为 Studio 语料，再复用本计划已交付的候选生成与审核能力。PDF、DOCX 等文件的本地解析和切片继续保留为后续 P1。

## 2. 要解决的问题

当前一条完整评测样本至少需要人工完成：

1. 整理语料片段。
2. 编写测试问题。
3. 编写标准答案。
4. 提炼答案核心要点。
5. 关联黄金召回语料。
6. 补充分类、难度、标签和可回答性。
7. 校验重复、引用和导出格式。

自动化的核心不是直接替代审核，而是自动完成第 2～6 步，把人工工作收敛为：选择语料、审核候选、修改少量错误、批准入库。

## 3. 目标工作流

```text
选择当前数据集中的语料
          │
          ▼
设置生成数量、题型、难度与预算
          │
          ▼
模型输出结构化候选问题
问题 + 标准答案 + 答案要点 + 元数据
          │
          ▼
本地确定性校验
格式 / 证据 / 重复 / 长度 / 引用
          │
          ▼
人工批量审核
批准 / 编辑后批准 / 拒绝
          │
          ▼
写入正式问题列表并自动关联黄金语料
          │
          ▼
沿用现有校验、快照和五 Parquet 导出
```

## 4. P0：基于现有语料生成候选评测问题

优先级：P0  
预计开发时间：3～5 天  
Codex 开发 token 成本：中到高  
模型运行成本：可控，主要由选中语料数和每段生成题数决定

### A0：生成配置与独立模型连接

预计：0.5～1 天

新增独立的“AI 生成配置”，不复用生产 WeKnora 评测接口契约：

- 配置名称。
- OpenAI-compatible Base URL。
- API Key。
- 模型名称。
- 超时时间。
- 逐条语料请求，并发固定为 1，避免模型费用和限流风险。
- 单段生成问题数，默认 1，上限 5。
- 单任务最大输入、输出和总 token。
- 可选费用单价，仅用于前端估算，不参与计费。

要求：

1. 配置只保存在本机独立目录，例如 `generation-connections/`。
2. API Key 文件权限为 `0600`，不写入数据集、快照、导出包和生成记录。
3. 只支持显式配置的固定请求路径，禁止 HTTP 重定向。
4. 生产/测试地址要求 HTTPS；本地回环地址可使用 HTTP。
5. 增加“测试连接”，只发送最小请求，不创建候选数据。

### A1：结构化候选生成

预计：1～1.5 天

在“语料”页增加“AI 生成评测问题”：

1. 支持勾选单条或多条语料。
2. 可设置题型、难度、每段生成数量和可选补充要求。
3. 后端读取选中语料，生成固定 JSON Schema，不接受模型返回任意字段。
4. 黄金语料关系由后端根据用户选中的语料建立，不能信任模型返回的 passage ID。

候选结构：

```json
{
  "question": "如何设置空间权限？",
  "answer": "进入空间信息后设置公开或私有权限……",
  "answer_key_points": ["进入空间信息", "区分公开与私有"],
  "category": "操作指导类",
  "difficulty": "easy",
  "tags": ["空间权限"],
  "answerable": true,
  "evidence_quotes": ["空间权限分为私有和公开两种"]
}
```

其中 `evidence_quotes` 只用于生成阶段校验，不进入 WeKnora 五 Parquet。审核通过后映射到现有字段：

| 生成字段 | Studio 字段 |
| --- | --- |
| `question` | `Question.Text` |
| `answer` | `Question.Answer` |
| `answer_key_points` | `Question.AnswerKeyPoints` |
| `category` | `Question.Category` |
| `difficulty` | `Question.Difficulty` |
| `tags` | `Question.Tags` |
| `answerable` | `Question.Answerable` |
| 用户选中语料 | `Question.RelevantPassageIDs` |
| 模型与模板版本 | `Question.AnnotationSource` |

### A2：确定性质量校验

预计：0.5～1 天

生成后先运行无需再次调用模型的本地校验：

- JSON Schema 和字段类型正确。
- 问题、答案和答案要点不能为空。
- 问题长度、答案长度和要点数量在配置范围内。
- `evidence_quotes` 必须能在选中语料中找到或达到规范化匹配阈值。
- 黄金语料必须存在且至少一条。
- 问题不能与当前数据集已有问题完全重复。
- 候选之间不能完全重复。
- 使用字符 n-gram/Jaccard 做低成本近似重复提示。
- 答案不得包含明显的“根据上述材料”等脱离真实问答场景的措辞。
- 模型返回的未知分类、难度和多余字段进入警告或被拒绝。

P0 不默认增加第二次 LLM Judge 调用，避免每条样本成本翻倍。人工审核仍是最终质量门槛。

### A3：候选审核工作台

预计：1～1.5 天

新增“AI 候选”区域：

- 展示来源语料、问题、答案、答案要点、分类、难度和校验告警。
- 支持批准、编辑后批准、拒绝。
- 支持多选批量批准或拒绝。
- 默认状态为 `draft`，批准后进入正式问题列表并改为 `approved`。
- 可以只批准部分候选；失败或拒绝项不污染当前数据集。
- 批量写入必须原子化，任何引用失效时整批不落库。

候选记录单独保存在 `generation-jobs/<dataset-id>/`，至少记录：

- Job ID、创建时间和状态。
- 数据集生命周期与版本。
- 选中语料 ID 和内容 SHA-256。
- 模型名称、生成参数和 Prompt 版本。
- token 用量、预估成本、重试次数和错误摘要。
- 每条候选的批准、修改或拒绝状态。

不保存 API Key；原始模型响应只在调试开关显式开启时保存，并必须脱敏。

### A4：成本和任务控制

预计：0.5 天

- 启动前展示语料数、预计生成题数、预计 token 上限和预估费用。
- 默认每段 1 题、单批 5 段、并发 1。
- 设置单任务硬 token 上限，达到上限后停止后续批次。
- 单批失败最多重试 1 次；结构化输出持续失败则保留失败原因。
- 支持取消尚未发送的批次。
- 使用“语料内容 SHA-256 + 模型 + 参数 + Prompt 版本”缓存结果。
- 相同输入默认复用缓存，用户明确选择“重新生成”时才再次计费。
- 页面持续显示已完成、失败、跳过、token 使用和预估费用。

### A5：P0 验收

预计：0.5 天

验收用例：

1. 选择 10 条已审核语料，每条生成 1 道题。
2. 模型返回 10 条结构化候选。
3. 本地识别空答案、无证据、重复问题和未知难度。
4. 人工批准其中 6 条、编辑批准 2 条、拒绝 2 条。
5. 正式数据集新增 8 个问题，全部正确关联原始语料。
6. 新问题可通过现有校验并导出五 Parquet ZIP。
7. ZIP 的 queries、answers、qrels、qas 数量和引用关系正确。
8. API Key 不出现在项目、快照、生成 Job、导出包或日志。
9. 同一输入再次执行时命中缓存，不产生模型费用。

## 5. P1：从文档批量构建语料和问题

优先级：P1  
预计开发时间：4～7 天  
前置条件：P0 稳定运行

能力：

1. 导入 TXT、Markdown、HTML、DOCX 或 PDF 文档。
2. 保留文档名、标题层级、页码或章节等来源信息。
3. 按标题和长度进行切片，生成待审核语料。
4. 语料审核通过后批量生成问题和标准答案。
5. 支持相邻片段组成多语料问题。
6. 对超长表格、目录、版权声明、空白页等低价值片段自动跳过。
7. 增加语料覆盖视图，显示哪些语料已生成问题、哪些尚未覆盖。

P1 仍然不直接连接生产知识库。生产文档可通过人工导出后导入 Studio，避免依赖不稳定的 WeKnora 版本和接口。

## 6. P2：提高真实性和难度覆盖

优先级：P2

### 6.1 真实问题导入

- 导入脱敏后的用户搜索词、客服问题或失败问答日志。
- 自动去重、聚类并映射本地语料。
- 对有语料支撑的真实问题生成标准答案。
- 对无语料支撑的问题标记为知识缺口，不强行生成答案。

真实问题比纯模型生成的问题更能代表生产场景，应成为后续数据集扩充的主要来源。

### 6.2 多类型样本

- 基础事实题。
- 操作步骤题。
- 条件与限制题。
- 对比题。
- 多片段综合题。
- 不可回答题。
- 权限和过滤条件题。
- 容易误召回的相似概念题。

### 6.3 可选二次评分

只有在明确接受额外成本时启用独立评分器，检查：

- 问题是否自然。
- 答案是否完全受语料支持。
- 答案要点是否完整。
- 难度标签是否合理。
- 问题是否存在歧义。

生成模型和评分模型应允许分别配置；不能把评分器结论直接当作最终人工批准。

## 7. 明确不做的事情

P0 阶段不做：

1. 不从生产 WeKnora 自动抓取知识库内容。
2. 不修改生产 WeKnora 后端。
3. 不允许 AI 候选绕过审核直接进入发布数据集。
4. 不用模型自行决定内部 passage ID。
5. 不默认执行昂贵的多轮生成、反思和多模型投票。
6. 不把 ROUGE、BLEU 或模型自评分当作事实正确性的充分证明。
7. 不在五 Parquet ZIP 中增加自定义字段或 manifest。

## 8. 推荐实施顺序

| 顺序 | 任务 | 优先级 | 预期价值 |
| --- | --- | --- | --- |
| 1 | A0 生成模型配置 | P0 | 建立独立、可控的模型调用能力 |
| 2 | A1 选中语料生成结构化候选 | P0 | 直接减少问题和答案编写工作 |
| 3 | A2 本地质量校验 | P0 | 降低幻觉和重复样本进入审核区 |
| 4 | A3 候选审核工作台 | P0 | 保证质量并支持批量入库 |
| 5 | A4 token、费用、缓存和取消 | P0 | 控制运行成本和重复费用 |
| 6 | A5 自动化验收与文档 | P0 | 保证现有导出能力不回归 |
| 7 | 文档切片与语料自动创建 | P1 | 从源文档开始形成完整流水线 |
| 8 | 真实问题与失败日志回流 | P2 | 提升评测集真实性和生产价值 |

## 9. P0 产品验收指标

- 人工不再从零编写问题和标准答案，只需审核或修改候选。
- 10 条语料可以在一次任务中生成并审核候选。
- 至少 60% 的候选可以直接批准或少量修改后批准。
- 100% 已批准问题拥有有效标准答案和黄金语料关系。
- 重复问题、无证据答案和失效引用不会进入正式问题列表。
- 单任务 token 与费用上限可见、可控、可中止。
- 相同输入重复生成默认不产生新的模型调用。
- 自动生成的数据继续通过现有校验并导出兼容 WeKnora 的五文件 ZIP。

## 10. 后续开发起点

建议立即从 A0 开始，先完成：

1. `GenerationConnection` 与本地安全存储。
2. OpenAI-compatible 结构化生成客户端。
3. 选中语料后生成候选的最小 API。
4. 固定 Prompt v1 和候选 JSON Schema。
5. mock 模型响应的契约测试。

完成 A0/A1 后即可先让用户体验“选择语料 → 生成候选”，再继续补齐审核工作台、成本统计和缓存，不需要等待 P1 文档解析能力。
