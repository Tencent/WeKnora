# Evaluation Dataset Studio 离线优先开发计划

## 1. 规划结论

- 状态：O0～O5 离线主线已完成；生产自动对接继续暂停
- 生效日期：2026-09-20
- 替代范围：替代原生产兼容计划中 R0、R4、R5 作为当前主线的安排
- 当前原则：生产 WeKnora 自动评测暂不可用时，工具仍应独立完成“数据集维护 → 标准数据包导出 → 外部执行 → 结果回导 → 报告与问题回流”的完整闭环

生产环境已经出现认证失败、任务状态查询 HTTP 500 等问题。由于生产版本和本地版本不一致，且短期不能修改生产 WeKnora，本阶段不继续猜测生产接口、不修改本地 WeKnora 后端来模拟兼容，也不把生产 API 修复作为工具交付的前置条件。

## 2. 产品边界

### 2.1 本阶段负责

1. 维护可复用的评测数据集及其版本。
2. 校验并导出严格的 WeKnora 五 Parquet ZIP。
3. 记录数据包的 SHA-256、契约版本、dataset ID 和人工部署信息。
4. 创建不访问远程接口的手工评测运行记录。
5. 导入外部系统产生的汇总结果和逐题结果。
6. 根据标准答案和相关语料关系生成离线评测报告。
7. 将失败样本筛选、导出或复制到下一版数据集。

### 2.2 本阶段不负责

1. 修复生产 WeKnora 的 HTTP 401/500。
2. 自动识别生产版本或试探多个写接口。
3. 自动在生产环境部署、上传或替换数据集。
4. 自动启动、轮询或取消生产评测任务。
5. 在缺少生产契约时开发 `production-<version>` Adapter。
6. 把本地 `local-current` Adapter 的成功行为当作生产兼容证明。

### 2.3 保留但降级的能力

- `local-current`：只用于本地同版本 WeKnora 联调，不作为生产入口。
- 生产连接配置：保留非敏感部署说明和 dataset ID；默认使用 `manual-export`。
- 生产 API 对接：代码和历史记录不删除，但标记为“暂停/实验性”，不进入当前验收标准。

## 3. 目标工作流

```text
维护测试问题、标准答案和相关语料
                  │
                  ▼
         校验并生成版本快照
                  │
                  ▼
      导出严格五文件 WeKnora ZIP
                  │
                  ▼
    人工部署并在目标 WeKnora 外部执行
                  │
                  ▼
      导入汇总 JSON/CSV 或逐题结果
                  │
                  ▼
       生成报告、定位失败样本并回流
```

工具不需要知道外部评测是通过生产 API、运维脚本还是人工流程运行，只要求导入结果符合 Studio 的中立结果契约。

## 5. 剩余主线任务与优先级

### O0：生产模式收口与防误操作

优先级：P0  
预计时间：0.5 天  
Codex token 成本：低

任务：

1. 生产环境新建配置时默认选择 `manual-export`。
2. `local-current` 用于 production 环境时展示明确的实验性警告。
3. 手工模式完全隐藏远程地址、API Key、知识库 ID、对话模型 ID 和重排模型 ID。
4. 页面明确区分“创建手工记录”和“发起远程评测”，避免用户误认为创建记录已经运行评测。

6. README 增加生产 API 暂停说明和推荐操作路径。

完成标准：用户在默认路径下不会意外向生产发送请求，也不会把本地记录误认为生产任务。

### O1：评测数据字段补齐

优先级：P0  
预计时间：1 天  
Codex token 成本：中

在不改变五 Parquet 导出契约的前提下，为本地问题增加可选评测元数据：

- 答案核心要点。
- 是否可回答。
- 期望召回文档。
- 禁止召回文档。
- 测试权限角色。
- 检索过滤条件。
- 测试集版本和标记来源。

实现要求：

1. 字段保存在项目 JSON、快照和备份中。
2. 五 Parquet ZIP 仍只导出 `text` 与关系字段，不写入额外列。
3. CSV 问题导入支持这些可选列，并提供新版模板。
4. 空字段保持向后兼容，不影响已有数据集。
5. 页面说明“相关语料”对应黄金召回片段；“期望文档/禁止文档”等字段用于报告，不等同于当前五文件契约。

完成标准：可以按现有评测集表头维护关键评测语义，同时继续导出生产可接受的严格五文件包。

实施进度（2026-09-20）：

- [x] 问题模型增加答案核心要点、可回答性、期望/禁止文档、测试角色、检索过滤条件、测试集版本和标记来源。
- [x] 页面支持新增、编辑和搜索扩展字段；新问题默认带入当前项目版本。
- [x] 问题 CSV 模板及中英文表头导入支持全部扩展字段。
- [x] `answerable` 支持中英文布尔值；检索过滤条件使用可校验的 `key=value` 格式。
- [x] 旧项目缺失扩展字段时保持兼容。
- [x] 项目 JSON、备份、快照和本地存储可保留扩展字段。
- [x] 契约测试确认扩展字段不会改变五 Parquet 的导出行或 Schema。
- [x] Go 测试、JavaScript 语法检查、差异检查和浏览器冒烟测试通过。

当前状态：O1 已完成，下一项为 O2 中立的外部结果契约与导入。

### O2：中立的外部结果契约与导入

优先级：P0  
预计时间：1～1.5 天  
Codex token 成本：中

在现有汇总 JSON 基础上新增版本化结果契约：

```json
{
  "schema_version": 1,
  "status": "success",
  "summary": {
    "retrieval_metrics": {},
    "generation_metrics": {}
  },
  "items": [
    {
      "question_id": 1,
      "actual_answer": "外部系统生成的答案",
      "retrieved_passage_ids": [0, 2],
      "retrieved_documents": [],
      "latency_ms": 1200,
      "error_message": ""
    }
  ]
}
```

任务：

1. 继续兼容当前汇总 JSON。
2. 支持逐题 JSON 和 CSV 导入。
3. 导入前展示预览、匹配数量、缺失问题、重复问题和未知 ID。
4. 阻止覆盖已完成记录；若需修正，创建新的导入版本。
5. 保存原始导入文件的 SHA-256 和契约版本，不保存凭据。
6. 对外部文档/片段无法映射内部 ID 的情况保留文本或外部标识，并标记“不可自动计算召回指标”。

完成标准：即使生产 API 不可用，也可以把外部评测结果稳定、可审计地带回工具。

实施进度（2026-09-20）：

- [x] 新增 `schema_version=1` 的中立逐题 JSON 契约，并兼容旧版汇总 JSON。
- [x] 新增逐题 CSV 导入，支持问题 ID、实际答案、召回片段/文档、耗时和错误信息。
- [x] 服务端预览匹配、缺失、未知、重复问题以及未知导出 passage ID。
- [x] 新导出和评测记录保存问题 ID 清单及“导出 PID → 内部语料 ID”映射，不修改严格五文件 ZIP。

- [x] 对已完成记录再次导入时创建带 `correction_of_run_id` 的修订记录，原记录不可覆盖。
- [x] 页面支持 JSON/CSV 切换、服务端校验预览和修订提示。
- [x] 外部结果导入表单仅在当前 Adapter 为 `manual-export` 时显示；其他模式只在存在手工记录时展示切换提示。

当前状态：O2 已完成，下一项为 O3 离线指标计算与评测报告。

### O3：离线指标计算与评测报告

优先级：P0  
预计时间：1～1.5 天  
Codex token 成本：中到高

任务：

1. 使用导入的 `retrieved_passage_ids` 与问题的黄金相关语料计算 Precision@K、Recall@K、Hit@K 和 MRR。
2. 展示总问题数、已运行数、失败数、缺失结果数和不可计算数，避免只展示平均值。
3. 按分类、难度、是否可回答、标签和来源分组。
4. 展示逐题详情：问题、标准答案、实际答案、黄金语料、实际召回、错误和耗时。
5. 支持筛选零召回、低召回、执行失败和缺少结果的样本。
6. 生成可下载的 HTML 报告、JSON 报告和失败样本 CSV。
7. 两次运行对比时区分改善、退化、新增缺失和不可比样本。

约束：

- 不使用字符串相等自动判定生成答案正确。
- ROUGE 等外部已有指标可以展示，但不能冒充事实正确性。
- 答案正确性只有在导入明确评分、人工审核或未来接入已确认的评分器后才给出结论。

完成标准：报告不仅显示汇总分数，还能回答“哪些问题失败、失败在召回还是生成、能否回流修正”。

实施进度（2026-09-20）：

- [x] 从评测记录关联的原始五 Parquet ZIP 读取问题、标准答案、黄金 qrels 和语料正文，避免当前项目继续编辑后污染历史事实。
- [x] 新评测记录保存分类、难度、可回答性、标签和黄金语料来源快照；旧记录兼容回退当前项目并显示警告。
- [x] 确定性计算逐题和宏平均 Precision@K、Recall@K、Hit@K 与 MRR，区分空召回和未提供召回信息。
- [x] 展示总数、已运行、失败、缺失、不可计算和零召回数量。
- [x] 支持按分类、难度、可回答性、标签和来源分组，并展示逐题问题、答案、黄金/实际召回、错误和耗时。
- [x] 页面支持全部、零召回、低召回、执行失败和缺少结果筛选。
- [x] 支持下载 JSON 报告、静态 HTML 报告和失败样本 CSV。
- [x] 两次运行按逐题 Recall 区分改善、退化、不变、新增缺失和不可比。
- [x] 明确不使用答案字符串相等判断事实正确性，旧汇总指标只作为外部指标展示。
- [x] Go 测试、JavaScript 语法检查和差异检查通过。

当前状态：O3 已完成，下一项为 O4 失败样本回流。

### O5：离线闭环验收与交付

优先级：P0  
预计时间：0.5 天  
Codex token 成本：低到中

验收流程：

1. 创建或导入一个至少包含 10 个问题的数据集。
2. 校验、创建快照并导出五文件 ZIP。
3. 确认 ZIP 只含五个 Parquet，记录 SHA-256。
4. 创建 `manual-export` 运行记录并填写部署说明。
5. 使用脱敏 fixture 模拟外部逐题结果导入。
6. 生成报告，验证汇总指标、失败筛选和运行对比。
7. 将失败样本复制为下一版数据集。
8. 重启工具，确认项目、导出、运行、结果和报告仍可读取。
9. 执行 Go 测试、JavaScript 语法检查和浏览器冒烟测试。

完成标准：不调用任何生产接口即可完整走通一轮评测生命周期。

实施进度（2026-09-20）：

- [x] 新增 10 题脱敏 fixture 的端到端自动化验收。
- [x] 自动完成数据集创建、校验、快照、严格五文件 ZIP 导出及 SHA-256/契约核对。
- [x] 自动创建 `manual-export` 运行并导入逐题 fixture，不发送任何远程请求。
- [x] 自动验证覆盖计数、本地检索指标、失败筛选数据和失败样本回流。
- [x] 使用同一 workspace 重新初始化存储，确认项目、运行、逐题结果、报告和回流数据集可复读。
- [x] 完整 Go 测试、JavaScript 语法检查、差异检查和浏览器冒烟测试通过；浏览器控制台无错误。
- [x] 最终本地服务已启动在 `http://127.0.0.1:8090`。

当前状态：O5 已完成，本轮离线优先开发主线交付完成。生产 Adapter 仍按第 6、7 节条件暂停。

## 7. 恢复生产自动对接的条件

满足以下条件后再新建版本化生产 Adapter，不直接修改 `local-current`：

1. 获得生产版本或构建标识。
2. 获得对应 API 文档、OpenAPI 或脱敏请求/响应样例。
3. 明确认证方式、空间权限、数据包部署和 dataset ID 规则。
4. 评测创建和查询接口在测试空间稳定可用。
5. HTTP 500 的服务端原因已经由生产维护方定位并修复。
6. 用户明确授权一次最小成本的生产验收。

恢复后按“只读契约审计 → fixture → 新 Adapter → 测试空间验收”的顺序执行。

## 8. 推荐开发顺序

严格按以下顺序推进：

1. O0：先消除生产误操作和界面歧义。
2. O1：补齐数据集评测语义。
3. O2：建立稳定的外部结果入口。
4. O3：完成可解释的离线报告。
5. O4：实现失败样本回流。
6. O5：完成独立于生产 API 的验收。

O0～O5 均为本轮交付主线。生产 Adapter、自动轮询和取消不再穿插开发。

## 9. 总体验收标准

1. 数据集、快照、导出包、手工运行、导入结果和报告可完整追溯。
2. 严格 WeKnora ZIP 的文件数、Schema 和引用关系通过自动回读测试。
3. 生产模式默认不发送远程请求，不要求 API Key。
4. 外部逐题结果能够与数据集问题稳定匹配并报告缺失/重复项。
5. 检索指标由黄金语料和实际召回结果确定性计算。
6. 生成指标明确区分“外部提供”“人工审核”和“工具无法判断”。
7. 报告能够定位失败样本并导出或回流。
8. 不修改生产 WeKnora，也不依赖生产 API 恢复才能完成验收。

## 10. 成本控制

- 继续使用 Go 标准库和原生 HTML/CSS/JavaScript，不引入前端框架。
- 报告首版使用服务端生成的静态 HTML，不引入图表库。
- 先支持固定的中立 JSON/CSV 契约，不开发拖拽字段映射器。
- 指标使用确定性本地计算，不调用 LLM 或 Embedding 服务。
- 每个 Codex 开发任务只处理一个 O 里程碑并同步测试和 README。
