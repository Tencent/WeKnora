# Evaluation Dataset Studio 生产 WeKnora 兼容开发计划

> 状态更新（2026-09-20）：生产端自动评测存在认证失败和任务状态查询 HTTP 500，短期无法通过本工具修复。本计划中的 R0、R4 和生产 API 版 R5 已暂停，不再作为当前开发主线。当前执行计划见 [`2026-09-20-evaluation-dataset-studio-offline-first-plan.md`](./2026-09-20-evaluation-dataset-studio-offline-first-plan.md)。本文保留为未来恢复生产版本适配时的契约与安全约束。

## 1. 规划结论

后续开发不再假设可以修改 WeKnora 后端，也不把本地 WeKnora 的接口行为视为生产契约。

工具改为以下结构：

```text
数据集编辑、校验与导出（稳定核心）
                  │
                  ▼
          WeKnora 版本适配层
        ┌─────────┼─────────┐
        ▼         ▼         ▼
  本地当前版本  生产版本   手工兼容模式
  Adapter       Adapter    Export Only
```

每个适配器只声明并使用目标环境真实支持的能力。生产没有的接口在页面中明确显示为“不支持”，不通过修改本地后端、猜测接口或伪造兼容来绕过。

## 2. 新增约束

1. 本地和生产 WeKnora 版本可能不同，API 路径、认证方式、请求字段、状态值和指标结构均可能变化。
2. 不能要求生产环境同步本地代码，也不能把新增后端接口作为工具可用的前置条件。
3. 生产环境可能只允许人工部署数据包，或根本不开放评测 API。
4. 生产 API Key 不落盘、不写日志、不进入项目 JSON、快照或评测记录。
5. 对生产环境的探测只允许无副作用的只读请求；发起评测前必须再次确认，因为会调用模型并产生费用。
6. 数据包格式也必须按生产版本核对，不能仅凭本地五文件实现推断生产兼容。

## 3. 当前基线

已经完成且继续保留：

- 数据集 CRUD、语料和问答关系维护。
- JSON/CSV/WeKnora ZIP 导入。
- 五 Parquet ZIP 导出及回读校验。
- 质量检查、统计、快照和导出历史。
- 本地当前版本的资源读取、评测启动、手动轮询和结果对比。
- API Key 不落盘、固定远程路径、禁止重定向和响应大小限制。

当前远程评测实现只能视为 `local-current` 适配器原型，不能直接宣称兼容生产。

## 4. 开发范围调整

### 4.1 近期必须完成

1. 生产 WeKnora 契约审计和兼容矩阵。
2. 将现有远程调用重构为版本适配器。
3. 增加环境配置、能力探测和兼容性报告。
4. 按生产真实契约实现生产适配器。
5. 数据包格式、dataset ID 和评测记录具备版本追踪能力。
6. 在生产测试空间完成最小成本端到端验收。

### 4.2 条件实现

以下功能只有生产接口明确支持时才开发：

- 自动轮询。
- 取消任务。
- 逐题评测结果。
- 服务端数据集上传、注册和版本切换。

如果生产不支持，工具提供明确的手工流程或结果导入能力，不修改生产后端。

### 4.3 继续延后

- AI 自动生成问题和答案。
- Embedding 语义去重和模型评分。
- Excel 与复杂字段映射。
- 多用户协作和服务端数据库。
- 复杂图表、富文本、拖拽工作流和桌面安装包。

这些事项在生产兼容闭环完成前不投入开发。

## 5. 兼容层设计

### 5.1 适配器能力

适配器统一暴露能力声明，不要求每个版本实现所有功能：

```go
type RemoteCapabilities struct {
    DiscoverKnowledgeBases bool
    DiscoverModels         bool
    StartEvaluation        bool
    PollEvaluation         bool
    CancelEvaluation       bool
    QuestionLevelResults   bool
    UploadDataset          bool
    ConfigurableDatasetID  bool
}
```

适配器负责：

- 远程路径和 HTTP 方法。
- 认证 Header。
- 知识库与模型响应转换。
- 评测请求字段转换。
- 任务状态和指标转换。
- 错误信息脱敏与归一化。

页面和项目存储只使用工具内部统一模型，不直接依赖某个 WeKnora 版本的 JSON。

### 5.2 首批适配器

| Adapter | 用途 | 能力 |
| --- | --- | --- |
| `local-current` | 当前本地 WeKnora | 保持现有资源读取、启动和轮询能力 |
| `production-<version>` | 生产 WeKnora | 契约审计完成后按证据实现 |
| `manual-export` | 未知或不开放 API 的环境 | 只导出、记录部署信息、允许手工填写远程任务结果 |

禁止提供“自动猜测并尝试多个写接口”的模式。

### 5.3 环境配置

工具支持本地保存非敏感连接配置：

- 配置名称，例如“本地开发”“生产”。
- 环境类型：local / staging / production。
- Base URL。
- Adapter ID。
- dataset ID 或部署说明。

不保存：

- API Key。
- 模型服务密钥。
- 登录 Cookie、Token 或其他凭据。

生产配置必须有醒目标识；读取资源和启动任务分别由用户显式触发，启动任务继续保留费用确认。

## 6. 剩余里程碑

### R0：生产契约审计

优先级：P0（下一阶段第一项）  
预计时间：0.5 天  
Codex token 成本：低到中

需要收集：

1. 生产版本号或构建标识。
2. 可用 API 文档、OpenAPI 文件，或测试空间的只读访问方式。
3. 认证 Header 和空间选择规则。
4. 知识库、模型列表接口及响应样例。
5. 评测启动、查询、取消和逐题结果接口是否存在。
6. dataset ID 规则和生产认可的数据包格式。

产物：

- `production-compatibility-matrix.md`。
- 脱敏后的请求/响应 fixture。
- 明确列出支持、不支持和无法确认的能力。

完成标准：不修改生产、不发起付费评测，也能确定后续适配边界。

实施进度（2026-09-18）：

- [x] 核对当前仓库的路由、认证能力、请求字段、状态值和指标结构。
- [x] 建立 [`production-compatibility-matrix.md`](./production-compatibility-matrix.md)，严格区分本地已确认与生产待确认。
- [x] 建立脱敏的 `local-current` 契约 fixture 基线。
- [x] 建立 [`production-contract-audit-checklist.md`](./production-contract-audit-checklist.md)，限定只读审计流程。
- [ ] 取得生产版本/构建标识、API 文档或只读响应。
- [ ] 用生产证据补齐矩阵并建立 `production-<version>` fixture。

当前状态：R0 本地基线已完成，生产事实待提供；不会在证据到位前编写生产 Adapter。

### R1：远程调用适配器重构

任务：

3. 增加 `manual-export` Adapter。
4. 使用现有 mock 响应保证重构前后本地行为一致。

完成标准：页面和存储层不再包含 `/knowledge-bases`、`/models`、`/evaluation` 等版本专属逻辑。

实施进度（2026-09-18）：

- [x] 定义统一 Adapter 接口、能力声明、资源、任务、状态、指标和错误模型。
- [x] 将当前版本的 URL 归一化、固定路径、认证 Header 和 JSON 解析迁入 `local-current` Adapter。
- [x] 增加 `manual-export` Adapter，远程能力均为不支持并返回明确错误。
- [x] 评测记录保存 `adapter_id`；旧记录缺失时兼容映射到 `local-current`。
- [x] 增加 Adapter 注册、手工模式和脱敏 fixture 回归测试。
- [x] 回归测试通过，页面现有数字状态值与 API 行为保持兼容。

当前状态：R1 已完成。版本专属路径仅存在于 `adapter_local_current.go`，页面 API 和评测记录使用统一模型。

### R2：环境配置与兼容性预检

优先级：P0  
预计时间：1 天  
Codex token 成本：中

任务：

1. 增加“本地/生产”连接配置选择。
2. 增加只读“检查兼容性”操作。
3. 分项展示连接、认证、知识库列表、模型列表和评测能力状态。
4. 生成可下载的脱敏报告，只保留路径、HTTP 状态、字段结构和 Adapter 结论。
5. 生产环境默认要求 HTTPS；loopback 本地环境允许 HTTP。

完成标准：在发起任何评测前，用户能够知道目标环境支持哪些能力、缺失哪些权限。

实施进度（2026-09-18）：

- [x] 增加本地、测试、生产环境连接配置；只持久化非敏感字段。
- [x] 增加 `local-current` 与 `manual-export` Adapter 选择。
- [x] 增加只读兼容性检查，远程检查仅使用四个固定 `GET` 端点。
- [x] 分项展示通过、待验证、失败、无权限、不兼容和不支持状态。
- [x] 支持下载脱敏 JSON 报告；不包含主机名、响应正文、资源名称或凭据。

### R3：数据包与评测版本追踪

优先级：P0  
预计时间：0.5～1 天  
Codex token 成本：中

任务：

1. 增加导出契约 profile，当前五文件格式登记为独立 profile。
2. 按生产审计结果决定复用现有 profile 或新增生产 profile。
3. 评测启动时不再硬编码 `dataset_id=default`，由 Adapter 能力和连接配置决定。
4. 导出历史记录 Adapter、契约版本、ZIP SHA-256、dataset ID 和部署状态。
5. 追踪信息只保存在本地记录，不向要求“严格五文件”的 ZIP 中加入额外文件。

完成标准：任意评测记录都能追溯到具体数据包、目标环境和兼容契约。

实施进度（2026-09-18）：

- [x] 支持将导出记录关联到连接配置、环境、Adapter 和 dataset ID。

- [x] 评测记录保存连接配置、环境、Adapter、dataset ID、契约 profile 和导出 ZIP SHA-256。

- [ ] 根据生产契约决定复用当前 profile，或新增版本化生产 profile。

### R4：生产 Adapter 实现

优先级：P0  
预计时间：1～2 天  
Codex token 成本：中到高

前置条件：R0 产物已确认。

任务：

1. 只实现生产真实存在的能力。
2. 将生产请求和响应映射到统一模型。
3. 为每个远程接口添加脱敏 fixture 契约测试。
4. 不支持的功能在 UI 禁用并展示原因。
5. 生产接口变化时通过新增 Adapter 版本处理，不覆盖旧 Adapter 行为。

完成标准：生产版本变化不会破坏本地适配器，生产不支持的能力不会误导用户。

当前状态（2026-09-20）：等待生产版本、API 文档或脱敏只读响应。遵循本计划约束，不在缺少证据时猜测生产接口。

### R5：生产端到端验收

优先级：P0  
预计时间：0.5 天  
Codex token 成本：中

验收顺序：

1. 在生产测试空间运行只读兼容性检查。
2. 导出一个最小数据集并人工部署。
3. 核对 ZIP 哈希和 dataset ID。
4. 显式确认费用后启动一次最小评测。
5. 轮询到终态，核对指标并重启工具确认记录仍可读取。
6. 确认项目、日志和本地文件中不存在 API Key。

如果生产不开放评测接口，则验收 `manual-export` 流程和外部结果导入，不把 API 自动运行作为完成条件。

手工兜底实施进度（2026-09-20）：

- [x] `manual-export` 可以创建不访问远程接口的本地评测记录。
- [x] 手工记录关联环境、dataset ID、导出契约和 ZIP SHA-256。
- [x] 支持导入经过校验的外部 JSON 指标，并参与已有指标对比。
- [x] 禁止使用外部结果覆盖远程 Adapter 创建的任务。
- [ ] 在生产测试空间完成真实数据包部署与结果回收验收。

### R6：条件增强

优先级：P1  
预计时间：按生产能力拆分  
Codex token 成本：中到高

1. 支持状态查询时增加指数退避自动轮询和停止按钮。
2. 存在取消接口时增加取消任务，并要求二次确认。
3. 存在逐题结果时增加失败样本列表和回流数据集功能。
4. 不存在结果 API 时，提供标准 JSON/CSV 结果导入。
5. 存在官方数据集上传接口时再增加上传；否则继续使用人工部署清单。

条件增强进度（2026-09-20）：

- [x] 标准 JSON 外部结果导入。
- [ ] CSV 外部结果导入；在确认生产实际导出列后实现，避免提前固化错误字段。

## 7. 开发顺序与任务边界

严格按以下顺序执行：

1. R0：先拿到生产事实，不写生产 Adapter。
2. R1：只重构，不增加远程行为。
3. R2：先做只读预检，不发起评测。
4. R3：补齐可追溯性和 dataset ID 配置。
5. R4：基于 fixture 实现生产 Adapter。
6. R5：用户明确授权后做生产测试空间验收。
7. R6：根据生产实际能力逐项决定。

每个 Codex 任务只完成一个里程碑，避免在生产契约未确认时同时修改后端、适配器和 UI。

## 8. 不再执行的方案

- 不为了工具功能去修改本地 WeKnora 后端，再假设生产会同步。
- 不硬编码生产版本路径或状态码。
- 不通过连续尝试多个写接口来“自动识别版本”。
- 不在生产环境自动替换 `dataset/samples/`。
- 不把生产 API Key 写入连接配置或浏览器持久存储。
- 不在生产不支持取消/逐题结果时制作只有 UI、没有真实能力的按钮。

## 9. 总体验收标准

1. 本地现有功能和测试全部保持通过。
2. 工具可以明确选择本地、生产或手工模式。
3. 每个环境显示经验证的能力矩阵。
4. 生产适配不依赖任何 WeKnora 后端代码修改。
5. 不支持的能力有清晰提示和可执行的手工兜底。
6. 数据包、dataset ID、Adapter 和评测结果完整关联。
7. 未经用户确认不会向生产发起评测或模型调用。
8. API Key 不落盘、不出现在日志和兼容性报告中。
