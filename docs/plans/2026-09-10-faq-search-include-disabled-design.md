# FAQ 管理搜索包含停用条目设计

## 背景

`POST /api/v1/knowledge-bases/{id}/faq/search` 使用 FAQ 向量索引进行语义搜索，但当前检索层和服务层都会排除 `is_enabled=false` 的条目。管理员因此无法在不重新启用条目的情况下验证停用 FAQ 的语义匹配效果。

社区已通过 #1450 和 #2392 明确停用 FAQ 不得进入聊天、Agent 或其他模型可见召回；#3154 和 #3157 则允许管理列表按启用状态筛选。本设计只补充管理搜索能力，不改变上述隔离规则。对应 Feature Issue 为 #3159。

## 接口

FAQ 搜索请求增加可选布尔字段 `include_disabled`：

- 不传或 `false`：只召回启用条目，保持现有行为。
- `true`：同时召回启用和停用条目。
- 返回结果继续携带 `is_enabled`，由调用方区分条目状态。

该字段只由 FAQ 管理搜索入口设置。聊天、Agent、知识库问答及其他 `HybridSearch` 调用保持默认值 `false`。

## 实现

在 `FAQSearchRequest`、`SearchParams` 和 `RetrieveParams` 中增加 `IncludeDisabled`。`SearchFAQEntries` 将请求字段传入其所有优先级搜索分支；知识库搜索服务只负责把字段复制到检索参数。

各检索后端在 `IncludeDisabled=false` 时继续应用现有启用状态条件，在 `true` 时省略该条件。FAQ 服务结果转换阶段同样只在默认模式下排除停用条目。该设计复用原有向量、阈值、标签优先级和排序流程，不增加数据库字段或索引。

## 兼容性与安全

布尔字段零值为 `false`，所有未显式设置字段的既有调用继续排除停用数据。只有 FAQ 管理搜索 Handler 可以接收外部参数，底层字段不会改变其他 API 的公开请求结构。

默认过滤和结果 hydration 的防护仍保留。测试需要证明普通检索调用不设置参数时继续生成启用状态条件，并证明 FAQ 管理搜索只有在显式设置时才保留停用结果。

## 测试

- FAQ 请求反序列化与服务参数透传。
- 无标签、一级标签、二级标签三个搜索分支的参数透传。
- FAQ 服务默认排除停用条目，显式包含时返回停用条目。
- 各检索后端默认保留启用过滤，显式包含时省略过滤。
- Swagger、Go Client 编译和相关 Go 包测试。
- 格式、静态检查和差异检查。
