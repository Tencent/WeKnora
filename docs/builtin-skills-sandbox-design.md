# 内置与精选 Skills、浏览器沙箱及旧镜像兼容方案

状态：设计方案，尚未实现。整理日期：2026-09-10。

## 1. 决策与范围

官方提供预装技能和依赖的沙箱模板，用户按空间和智能体启用。首批为 7 个办公分析技能，以及 agent-browser 和浏览器观看、接管能力。完整图形桌面作为后续增强模板。

内置技能不再要求用户逐个下载依赖、安装和生成快照。自定义技能继续使用现有目录、安装、验证、镜像快照流程。

升级 WeKnora 应用本身不替换用户的镜像，不销毁已有沙箱，不自动启用新技能。旧镜像继续承载已有功能；只有已经确认存在且可调用的新能力才开放。

本方案的首版是需要沙箱的执行型技能，不包含脱离沙箱的纯指令技能。

同时提供“技能发现”入口，展示内置技能与精选外部技能。外部推荐可以仅有原创简介和原站链接，不等于已安装、可在本地执行或具有转发源码的许可。

### 2.1 技能来源

| 技能 | 上游目录 | 首版交付能力 |
|---|---|---|
| xlsx | NousResearch/hermes-agent: skills/productivity/xlsx | 工作簿生成、读取、编辑、公式重算、图表 |

| pdf | NousResearch/hermes-agent: skills/productivity/pdf | 创建、提取、合并拆分、表单、水印 |
| exploratory-data-analysis | K-Dense-AI/scientific-agent-skills: skills/exploratory-data-analysis | CSV/TSV/JSON 数据概览、缺失值与异常分布检查 |
| statistical-analysis | K-Dense-AI/scientific-agent-skills: skills/statistical-analysis | 常用统计检验、效应量、回归、诊断 |

上述办公和分析技能声明 MIT；agent-browser 仓库为 Apache-2.0。落地时固定上游 commit，保留许可证和修改记录，逐项确认依赖、字体及附带资源的许可。能力依据上游文档及部分脚本检查，尚未在本项目环境完成验证。

OCR 大模型、贝叶斯计算、外部研究 API、桌面应用不进入首版默认依赖。适配后的指令只能承诺实际打包并通过验收的能力。

### 2.2 发布模板

| 模板 | 内容 | 使用方式 |
|---|---|---|
| base | 现有轻量 Shell、文件、Python/Node 环境 | 保留给已有部署与自定义用途 |
| office-browser | 7 个办公分析技能、浏览器技能、系统依赖和中文字体 | 首版推荐；浏览器按需启动 |
| desktop | 在 office-browser 上增加显示服务、窗口管理器、远程桌面 | 后续可选；用于 Linux GUI 软件 |

Docker 发布不可变镜像引用；Cube、E2B 从同一发布内容分别构建符合其启动协议的模板。镜像相同不代表后端连接能力相同，画面流必须逐后端验证。

浏览器自动化可以无头运行。用户观看和接管优先采用 agent-browser 的画面流及输入协议。完整桌面另采用 Xvfb、轻量窗口管理器、VNC/noVNC 等组件。Linux GUI 模板不承诺运行 Windows Office COM 等平台专属技能。

## 3. 应用、镜像和资源的分工

应用负责官方目录、启用配置、资源读取、兼容检查和连接授权。镜像负责实际脚本、模板、解释器环境、LibreOffice、字体和浏览器。

建议目录：

```text
internal/builtin/skills/
  registry.go
  catalog.json
  sources.lock.json
  packages/<skill>/
    SKILL.md
    LICENSE
    UPSTREAM.md
    requirements.txt
    scripts/
    references/
  bundles/<skill>.zip

# 沙箱内部
/opt/weknora/builtin/
  manifest.json
  skills/<skill>/
    SKILL.md
    scripts/
    .venv/
```

系统工具共享，技能 Python 环境独立。沿用当前技能目录内 `.venv` 的环境选择约定，减少特殊处理。原始文件位于 `/workspace/input`，成果位于 `/workspace/output`，浏览器 profile 位于会话私有目录。

同一次构建产生应用内资源包与镜像内文件。ZIP 固定文件顺序、时间戳等元数据，保证相同内容具有相同摘要。应用通过 `go:embed` 携带当前发布资源；历史已使用资源保存到持久存储，供旧会话读取。

包适配包括工具名映射、`$WEKNORA_SKILL_DIR` 路径、中文触发条件、引用资源完整性和固定依赖。当前镜像使用 Python 3.11，分析依赖须选择验证兼容的版本，或显式提供该技能所需解释器；不直接照搬上游最新依赖。

## 4. 能力识别与版本一致性

### 4.1 区分四个概念

- 应用发布版本：后端和前端提供哪些协议、工具和界面。
- 镜像身份：实际使用的 Docker digest 或 provider 不可变模板/快照身份。
- 技能包版本：每个技能的 ID、适配版本、内容摘要。
- 会话运行版本：这个会话的沙箱实际创建时使用的环境。

不能用 `main` 标签、模板名称、后端类型或当前配置版本替代运行版本。已有租户快照通常优先于基础模板；只修改基础镜像并不能更新已安装技能的快照。

### 4.2 镜像清单与有效能力

建议在清单中描述以下逻辑字段（字段名及协议版本在实施时确定）：

```text
schema_version
runtime_protocol
build_id
profile
capabilities: shell, browser_automation, browser_stream, desktop
skills[]: builtin_id, name, package_version, bundle_sha256, resources_path
```

最终镜像 digest 由发布目录在镜像外绑定，不将最终 digest 写回镜像造成自引用。内置清单的散列与发布记录绑定；未知自定义镜像的清单是能力声明，不能赋予官方来源身份或额外权限。

有效能力 = 应用协议支持 ∩ 镜像声明及运行检查 ∩ 后端连接能力 ∩ 空间/智能体策略。

例如：镜像中 Chrome 可运行，但后端尚未提供画面代理，则可以自动化和截图，不能显示“支持实时接管”。

配置验证可通过管理员发起的临时检查沙箱完成，检查后释放。普通列表读取不创建沙箱。结果按租户、配置、后端身份、不可变镜像身份缓存；已有会话在连接/恢复时核对实际身份，并在首次使用相应能力时做有界就绪检查。

状态区分 `verified`、`legacy`、`unknown`、`incompatible`。连接失败是未知/检查失败，不等同于永久不支持，也不触发销毁重建。

### 4.3 会话绑定

为会话运行记录增加镜像身份、清单摘要、技能包映射和协议版本。配置层记录未来新建沙箱的预期能力，会话层记录实际能力。

`read_file`、技能列表、技能执行必须使用相同的会话解析结果。优先使用已固定摘要的资源包；历史包未保存时，可从当前沙箱内校验过的技能文件树读取，不能回退为应用最新版说明。

旧绑定新增字段可为空，不改变现有绑定的有效性。旧会话缺少版本信息时尝试只读检查；无法确认的新技能不暴露，已有功能沿用兼容路径。

历史资源按实际引用保留。回收同时考虑配置、活跃/暂停会话、快照和回退保留期，不能仅按“最新 N 个版本”删除。

## 5. 旧镜像如何处理

### 5.1 兼容矩阵

| 用户环境 | 应用升级后的行为 | 推荐操作 |
|---|---|---|
| 旧官方镜像，没有内置清单 | 原有聊天、Shell、文件和已安装技能照常；新能力标为未验证 | 新建使用 office-browser 模板的配置 |
| 旧镜像支持 Shell 和依赖安装 | 可检查是否满足某个技能的适配条件 | 需要时为派生配置安装单个兼容包 |
| 已有自定义技能快照 | 继续使用原快照；不直接替换基础模板 | 创建新配置，按实际安装版本迁移自定义技能 |
| 自定义镜像已有 Chrome | 验证浏览器、CLI 和协议后开放自动化；画面能力另检查 | 满足条件则复用，否则使用官方模板 |
| 镜像有浏览器，后端不支持画面代理 | 自动化/截图可用，观看接管不可用 | 完成后端适配或选择支持的配置 |
| 新模板，已有旧会话沙箱 | 新旧环境分别识别；旧会话不获得虚假的新技能列表 | 新会话使用新配置，旧会话继续完成任务 |
| 新镜像协议超出当前应用支持 | 明确不兼容；可独立使用的旧协议能力按验证结果开放 | 升级应用或选择兼容模板 |
| 模板无法访问、检查失败 | 保留配置和旧运行绑定；显示具体错误，可重试 | 修复连接/权限后重新检查 |

没有清单不意味着没有 Shell 或已有技能。不能将“无法确认内置能力”解释为“整个旧沙箱不可用”。也不能仅凭 `command -v chromium` 就宣布浏览器接管可用。

### 5.2 默认升级方式：创建新配置

设置页提供“创建新版沙箱配置”，默认迁移路径：

1. 读取旧配置，列出镜像、已安装技能、使用它的智能体及会话数量。
2. 在选定后端创建 office-browser 模板对应的新配置，保留旧配置。
3. 迁移选定自定义技能：固定当前安装包摘要和依赖信息，在新配置上重新安装验证。
4. 检查内置技能、自定义技能、浏览器及画面通道，显示逐项结果。
5. 管理员选定智能体后切换其未来使用的配置。已有沙箱仍按原配置绑定运行。
6. 新环境验证稳定、旧会话结束后，另行清理旧配置和资源。

不复制运行中的浏览器 profile、临时工作区、进程或登录状态到公共模板。空间/用户凭据不是技能包内容，配置迁移只在授权的原空间范围内处理，不能进入镜像或日志。

迁移从每个安装实例实际使用的包开始，不从可变的目录最新版本开始；旧归档缺失时将该项标为阻塞，保留原环境，不静默换版本。相同目标和摘要可重试且不重复安装；同一目标配置的快照构建串行执行。

新配置验证失败不切换智能体。切换后需要回退时，将未来会话重新指向旧配置；已经在新配置运行的会话仍保留其绑定，不能宣称可以原样热回退。

### 5.3 可选兼容补装

旧镜像的 OS、CPU 架构、解释器、系统包安装和快照能力满足要求时，可以用维护沙箱构建包含某个技能的派生环境。正式聊天过程中不自动升级 OS、批量安装依赖或启动桌面服务。

优先为新配置构建派生环境，验证后启用。office/browser 各自有兼容配方；无法安装系统依赖或没有受支持的快照链路时，推荐官方模板，不伪造安装成功。

首版必须支持旧环境继续使用及新配置迁移。任意旧镜像的自动补装不是首版前提；只有经过验证的兼容范围才展示补装入口。

### 5.4 更新生效范围与数据保留

当前实现已有 `skill_rollout`：空值和 `next_turn` 会在后续边界重建已有沙箱；`new_session` 保留旧沙箱。旧配置默认值不在本次应用升级时批量改写。

本方案的环境升级默认采用新配置；新增推荐配置使用 `new_session`。前提是完成会话技能版本识别，避免旧环境获得新版本技能说明。

如果以后提供“当前会话切换环境”，应单独设计数据导出、恢复和失败回退。聊天记录保留不等于沙箱工作区、依赖或登录状态保留。首版不承诺活沙箱原地迁移，也不因升级提示自动标记旧绑定为 stale。

这里的“新会话生效”准确指之后新建的沙箱；没有活沙箱的历史聊天再次创建环境，也应按实际创建规则说明其版本。

## 6. 内置与自定义技能的统一使用

官方目录随应用可见，空间启用记录按 `builtin_id` 保存；不为预装技能伪造租户安装完成记录。智能体沿用技能选择能力，执行前结合实际沙箱进行过滤。

运行时扩展现有 Skills Manager，使内置来源与租户来源可以组合，并按解析后的来源选择资源路径和环境。技能身份记录来源和摘要，调用名称仍可使用 `xlsx` 等简短名称。

已有同名自定义技能继续保留，新内置技能显示冲突并保持未启用；用户处理冲突后才激活。不得静默覆盖或按随机加载顺序决定来源。后续可扩展显式别名，但不作为首版要求。

历史 `AllowedSkills` 空值目前表示全部允许。新增官方技能仍先经过空间显式启用，应用升级本身不扩大旧空间能力。已明确选择“全部”的智能体是否获得随后由管理员启用的技能，按界面说明执行；需要固定集合的智能体存储显式选择。

停用控制产品暴露和工具调用，不物理删除镜像文件；现有通用 Shell 能访问文件，停用不是操作系统隔离边界。需要完全去除某技能代码的部署应使用不含该技能的模板。

## 7. 浏览器、图形桌面和文档视觉检查

首版聊天侧提供按能力显示的“文件 / 终端 / 浏览器”面板。用户接管后，后端禁止 Agent 同时操作该浏览器；交还后重新获取页面状态，再继续工具调用。断线、重连、暂停恢复和会话结束都有明确控制权状态。

增加独立的会话浏览器连接能力接口，后端适配 Docker、Cube、E2B。仅依据镜像声明或 provider 名称不能判断是否支持。连接代理验证租户、会话访问权限以及观察/控制权限；沙箱入站凭证由服务端使用，不直接暴露 CDP/VNC 控制端口。

浏览器端口、进程、profile、下载目录与会话绑定。浏览器重启和沙箱恢复后重新检查就绪，页面连接不能隐式启动收费沙箱。新建/恢复通过明确的会话运行入口进行。重复连接与关闭应幂等，桌面流和浏览器进程按需运行。

文档视觉检查单独增加受限的沙箱图片读取/分析能力，复用应用已配置的视觉模型，限制会话文件范围、类型、大小和图片数量。当前文本 `read_file` 抑制二进制，不能替代此能力。未配置视觉模型时保留文件生成，明确没有完成视觉检查。

## 8. 精选外部技能与链接目录

### 8.1 产品入口与分发方式

建议保留“我的技能”用于空间现有能力，增加“技能发现”，其中提供“内置技能”和“精选外部”分类。推荐目录是 WeKnora 维护的选择，不表示上游对 WeKnora 的官方背书。

| 分发方式 | 平台保存的内容 | 主操作 | 何时进入 Agent 可用技能列表 |
|---|---|---|---|
| `builtin` | 随应用和镜像发布的技能包 | 启用 / 创建兼容配置 | 启用且实际环境匹配后 |
| `remote_install` | 目录元数据、固定来源和许可依据；安装时拉取合法可用的包 | 添加并安装 | 安装验证完成且被允许后 |
| `external_link` | 名称、作者、原创简介、原站及许可证链接 | 查看原站 / 使用说明 | 不进入本地可执行技能列表 |

许可未知、来源尚未核对或不适合本地分发的推荐项默认采用 `external_link`。安装能力必须由后端按分发方式判断，不能只隐藏前端按钮。外部链接条目不能经推荐目录接口触发包下载、缓存、注入或安装；若以后获得额外授权，应经过发布审查后修改分发方式。

`remote_install` 不只依据许可证名称开放：还要确认具体包的来源、版本、附带资源及执行依赖。技能许可与 API 服务额度分开显示。首版可以先只发布内置和外部链接两类，复用已有自定义来源安装能力处理已经核对的开放技能。

### 8.2 Anthropic 文档技能的处理

Anthropic 的 docx、pdf、pptx、xlsx 在其仓库 README 中被标为 source-available，而非开源。2026-09-10 核对的单独许可证覆盖代码、提示词、资源等内容，并限制服务外保留、复制、衍生及分发。因此本方案只将这四个条目作为外部参考入口，不提供“安装到 WeKnora”的推荐操作。

卡片示例：

```text
Claude PowerPoint Skill
提供方：Anthropic
用途：演示文稿创建与编辑（WeKnora 自行撰写简介）
使用方式：外部服务
许可：专有条款 / 源码可见
操作：官方使用说明 | 查看原始仓库 | 许可条款
```

链接指向公开的原始目录和官方使用说明，不复制原始 SKILL.md、脚本、模板、截图或其他受限材料作为平台资产。不把“用户点击安装”视作获得了复制到自建沙箱的许可。仅提供链接是本方案的产品边界，不是对用户其他用途的法律授权结论。

如未来希望在 WeKnora 内调用这些能力，可以另行评估 Claude 官方 Skills API：通过上游服务执行，单独处理凭据、文件传输、费用及成果返回。该路线不等于把其技能源码装入 WeKnora 沙箱，也不在首版实施范围。

### 8.3 推荐目录的数据与维护

建议目录字段：

```text
id, name, publisher, summary, categories
distribution: builtin | remote_install | external_link
homepage_url, source_url, license_url, license_label
usage_docs_url
verified_ref, reviewed_at
runtime_requirements
```

上游版本与能力核对日期分别记录；外部链接不需要伪造包摘要。安装型条目必须固定已经验证的来源版本。目录随发布维护，不在用户打开页面时抓取所有仓库或执行远端指令。

旧镜像用户同样可以浏览外部推荐。内置/可安装项显示该配置的兼容结果和升级入口，纯链接项只表示在外部查看，不显示误导性的“当前沙箱可用”。

参考：[Anthropic 仓库说明](https://github.com/anthropics/skills)、[PPTX 单独许可证](https://github.com/anthropics/skills/blob/main/skills/pptx/LICENSE.txt)、[官方 Skills 使用方式](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)。

## 10. 实施顺序与验收

1. **运行版本和旧镜像兼容基础**：能力清单、探测、旧绑定兼容、会话版本固定；不改用户镜像。
2. **镜像与内置技能闭环**：先以 xlsx 验证预装→启用→调用→下载，再完成七个技能和中文样例；加入技能发现和只读精选外部目录。
3. **浏览器完整闭环**：预装浏览器、逐后端验证、画面代理、接管交还、会话生命周期；首版发布范围包含此阶段。
4. **旧配置迁移与发布**：新模板发现、迁移任务、自定义技能重装、显式切换与回退；完成旧版本升级测试。
5. **后续增强**：完整桌面、更多兼容补装配方、当前会话环境迁移、额外专业技能。

核心验收：

- 应用升级后，旧镜像、旧配置、旧绑定和已有技能仍可用；不访问目录就创建新沙箱。
- 缺少清单、清单协议不兼容、浏览器依赖不足、画面代理不可达分别有准确状态。
- xlsx 公式重算核对结果；Word/PPT/PDF 使用中文模板并渲染检查，不能只看退出码。
- 数据分析使用已知输入核对数值；图表核对中文标注和导出文件。
- 同名技能不覆盖；未启用技能不进入提示词；并发启用、检查、迁移可重试。
- 精选外部链接不触发包下载、缓存或提示词注入，不伪造安装状态；直接调用目录安装接口也无法安装 `external_link` 条目。
- 两个会话分别运行旧/新镜像时，技能列表、资源说明和执行版本对应各自环境。
- 浏览器观看、接管、交还、断线重连、暂停恢复、文件下载可用；跨空间和无权会话不能连接。
- 迁移失败不改变旧配置或智能体；缺失历史包明确阻塞；凭据不进入公共镜像。
- 新旧模板并存时能回退未来会话，暂停中的旧沙箱及其资源不会被过早回收。
- 在 Docker、Cube、E2B 上分别验证声明支持的能力；未通过的 provider 能力不标为可用。
