# 备份与恢复

WeKnora 内置全实例备份/恢复 API(对应 [#675](https://github.com/Tencent/WeKnora/issues/675) 与 [#2887](https://github.com/Tencent/WeKnora/issues/2887))。所有端点仅**系统管理员**可调用——备份包含全部空间的数据与加密凭据。

## 端点一览

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/v1/backups/export` | GET | 即时生成备份并下载(tar.gz) |
| `/api/v1/backups` | POST | 在服务器上创建快照(可附 `{"note":"..."}` 备注) |
| `/api/v1/backups` | GET | 列出服务器上的快照 |
| `/api/v1/backups/{id}/download` | GET | 下载指定快照 |
| `/api/v1/backups/{id}` | DELETE | 删除指定快照 |
| `/api/v1/backups/restore` | POST | 恢复(按快照 id 或上传备份文件) |

## 备份内容

| 内容 | 包含 | 说明 |
|------|------|------|
| PostgreSQL 全库 | ✅ | 用户、空间、模型配置(含加密 API key)、知识库、文档、切片、会话、MCP/数据源配置、系统设置；向量仅在检索引擎为 Postgres/ParadeDB 时随库导出 |
| 上传文件 | ✅(local 存储) | 原始文档、聊天附件、图片产物;路径相对 `LOCAL_STORAGE_BASE_DIR` |
| Redis 队列 | ❌ | 瞬态数据,恢复时会被主动清空 |
| 外部向量库 / Neo4j / 对象存储 | ❌ | Weaviate、OpenSearch、MinIO/COS/S3 等不在归档内,清单会如实标注 |
| `config.yaml` / 环境变量 | ❌ | 属部署环境;跨实例迁移时需手工对齐(见下) |

归档结构:`manifest.json`(版本/时间/包含项)+ `db.sql.gz`(pg_dump)+ `files.tar`(上传文件)。

## 使用示例

```bash
TOKEN="<系统管理员的 JWT>"

# 一键导出到本地文件
curl -H "Authorization: Bearer $TOKEN" \
     -o weknora-backup.tar.gz \
     http://localhost:8080/api/v1/backups/export

# 服务器侧创建快照(适合脚本定期执行)
curl -X POST -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"note":"每周例行"}' \
     http://localhost:8080/api/v1/backups

# 恢复(二选一:快照 id 或上传文件;confirm 必须为 true)
curl -X POST -H "Authorization: Bearer $TOKEN" \
     -F "snapshot_id=weknora-snapshot-20260830-120000" -F "confirm=true" \
     http://localhost:8080/api/v1/backups/restore

curl -X POST -H "Authorization: Bearer $TOKEN" \
     -F "file=@weknora-backup.tar.gz" -F "confirm=true" \
     http://localhost:8080/api/v1/backups/restore
```

快照默认存放在本地存储卷内(`LOCAL_STORAGE_BASE_DIR/.weknora-backups`,如 `/data/files/.weknora-backups`),与 `data-files` 卷一起持久化。可用环境变量 `BACKUP_DIR` 覆盖。该目录不会打进 `files.tar`,恢复时也不会被覆盖。

上传归档的默认上限为 4096 MB(`MAX_BACKUP_ARCHIVE_SIZE_MB`),Nginx 对 `POST /api/v1/backups/restore` 单独放宽,不占用知识库 50MB 上限。

## 恢复语义(重要)

恢复采用**整库 + 本地文件替换**:

1. 校验归档(manifest、驱动、版本;目标实例版本必须 ≥ 备份版本);
2. 若归档包含文件,先解到暂存目录(失败则中止,不碰现网库);
3. **必须**先对当前状态创建 `pre-restore-*` 快照作为回滚点——快照失败则拒绝恢复;
4. drop/recreate 数据库后,以**单事务**导入转储。导入使用与 HTTP 请求脱钩的 context,避免浏览器关闭或代理超时在 DROP 之后杀掉 psql;
5. 用暂存目录**替换**(而非合并)本地上传文件,已删除的旧文件不会留下;
6. 清空 Redis 队列(旧任务引用已替换的 ID);
7. 返回结果要求**重启实例**;重启后 `AUTO_MIGRATE` 会把老版本 schema 自动升到当前版本。

恢复窗口内进行中的请求会报错,属于预期行为,建议在维护窗口执行。

## 跨实例迁移

备份中的加密字段(模型 API key、MCP token、数据源凭证等)使用源实例的 `SYSTEM_AES_KEY` 加密。迁移到新实例时:

1. 新实例设置与源实例相同的 `SYSTEM_AES_KEY` 环境变量(32 字节);
2. 上传备份文件执行恢复;
3. 重启新实例。

未设置时,加密字段会显示为空(可在界面重新填写),其余数据不受影响。

## 依赖与限制

- Postgres 导出/恢复依赖 `pg_dump` / `psql`,且**主版本必须与服务器一致**(官方镜像安装 postgresql-client-17,对应 ParadeDB pg17;自编译部署请安装匹配的 postgresql-client);
- SQLite 部署支持导出(`VACUUM INTO`);恢复需停机后手工替换数据库文件(接口会明确报错提示);
- 远程对象存储(minio/COS/S3/OSS/TOS)的文件暂不包含在备份中;
- 按知识库粒度的选择性备份、定时调度、归档加密规划中。
