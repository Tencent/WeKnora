## 1. 测试目标与范围

验证 Outline 按 Collection 单向同步到 WeKnora，在首次全量、增量、文档退出范围、异常和任务恢复时保持明确的文档身份及最终收敛。重点不是只证明“成功拉到一篇文档”，而是证明失败文档不会因游标推进被遗漏、不会因列表不完整误删、不同来源不会互相覆盖。

测试分开验证三个阶段：源端读取正确、内容接收正确、知识解析并可检索。SyncLog.success 不能替代 parse_status=completed，也不能替代查询结果及引用验证。

覆盖后端连接器、共享数据源服务改动、前端、PostgreSQL、单实例 Lite/SQLite、安全和万篇级运行。OAuth、Webhook、源端 ACL 映射、双向写回、子树选择、私有附件本地化不在本期正向功能验收范围；需要验证界面和文档没有宣称这些能力。

所有源端创建、移动、归档、删除及权限变更只在授权的隔离测试空间执行。本文不授权针对生产知识执行故障或删除演练。

### 1.1 优先级与状态

| 等级 | 定义 | 准入要求 |
| --- | --- | --- |
| P0 | 错删、漏同步、越权、凭据泄漏、身份覆盖、不可恢复、基础流程不可用 | 全部通过，未通过或未执行阻断发布 |
| P1 | 兼容、边界、交互、诊断及容量的重要能力 | 首期适用用例全部通过 |
| P2 | 非关键显示和辅助体验 | 可记录已知问题，由发布负责人明确接纳；不得影响 P0/P1 |

用例状态只取“待执行、通过、失败、阻塞、不适用”。本稿所有用例均为待执行。“不适用”必须说明部署边界和审批依据，不能用于跳过既定首期要求。文档链接和结构检查属于文档 QA，不改变功能用例状态。

| 账号/凭据 | 权限和用途 |
| --- | --- |

最小权限验证不能只观察 Token scope：端点可能另要求账号角色。同步 Key 不具备创建、更新、删除或恢复文档的写权限；OL-MUTATOR 与同步凭据分离。真实 Key 通过环境秘密注入，不进入 fixture、HAR、截图、日志或测试报告。

## 5. 万篇级容量与性能执行方案

### 5.1 数据规模与隔离方法

DS-SCALE 使用固定随机种子，1,000 和 10,000 篇采用相同分布：90% 约 8 KiB、9% 约 64 KiB、1% 约 1 MiB。标题包括中文，层级深度覆盖 0～8；至少 10 个 Collection。另设 100 篇变化、150 篇失败及 1,000 篇 pending 的压力变体，不将这些故障数据混入零变化基线。

分别执行两类测试：

1. 连接器容量测试：模拟 API 和稳定的确认 handler，排除模型、解析器并发和下游缓存，观察正文缓冲和游标开销。使用可控时钟加速等待时，必须标注“加速的容量测试”，不能据此报告真实吞吐。
2. 完整流水线测试：保留默认 1 请求/秒和真实解析/索引，使用固定环境和模型测接收及可检索耗时。模型吞吐不满足当前硬件时记为环境瓶颈，不用它掩盖来源身份或恢复缺陷。

### 5.2 指标与阈值

| 指标 | 验收标准 |
| --- | --- |
| 来源身份正确性 | 健康数据集最终有效身份集合与 manifest 一致；不同身份不能因同正文减少 |
| 单份游标 | 10,000 篇常规数据不超过 10 MiB；高 pending 变体保留全部失败身份并单独记录大小 |
| 连接器内存 | 1,000 → 10,000 篇时，隔离测试稳态 heap_inuse 增量不超过 128 MiB，峰值 RSS 增量不超过 256 MiB；测 3 次取中位数并附峰值 |
| 正文缓冲 | 不能出现总正文数组常驻；通过 heap profile、当前页与已释放页对象证明，而非只看一次 RSS |
| 检查点 | ENV-PERF 下 30 个有效样本的写入 p95 不超过 2 秒；失败要停止提交，不可绕过持久化 |
| 无变化增量 | Created=0、Updated=0、无新增解析任务；允许 API 列表仍传全文 |
| 1% 变化 | 对应 100 个身份进入变化处理；不把重复请求或幂等重放算成新增身份 |
| 恢复 | 故障解除后最终收敛，未完成 Collection 可以从首页重读；已确认同版本不能整批重建 |
| 查询计划 | PG 复用现有外部 ID 索引；SQLite 新增等价索引可被实际身份查询使用 |
| 总耗时 | 报告实测接收/解析/索引耗时、请求量与限流时间；不以预设固定分钟数替代正确性 |

阈值是首期工程验收目标，不是生产 SLA。超标时先确认数据、硬件和下游隔离是否符合条件；不能以“内存有界”为由裁剪已知文档、pending 或错误恢复信息。

### 5.3 故障注入点

| 注入点 | 方法 | 必须观察的状态 |
| --- | --- | --- |
| 列表第 2 页 | 500、超时、重复页、提前空页 | scan incomplete，无删除提交 |
| 详情读取 | A 失败而 B 成功，之后 A 版本不变 | A 保持 pending，下轮重试 |
| 文件保存 | 对指定文档返回一次存储错误 | 不确认成功版本；恢复后不漏文档 |
| 解析任务入队 | 返回知识对象但标记 failed | 接收确认是 failed，UI 非假成功 |
| 知识删除 | 删除级联或硬删除返回一次错误 | pending_deletions 继续保留 |
| 检查点 | DB 返回错误或客户端收到不确定提交结果 | 停止当前运行；重启读取真实持久状态后幂等恢复 |
| worker 退出 | 已完成 30%/70% 后终止 | 新 worker 从最后检查点恢复 |
| 429 与取消 | 有效 Retry-After 等待时取消 | 无继续请求、无忙等、已保存状态可用 |
| 租约续约 | 续约失败/其他持有者已取得锁 | 旧 worker 停止新操作，不误删他人锁 |

不得用只存在于生产的真实 Key 或原始正文构造失败样本。数据库和对象存储故障使用测试专用 namespace 或 stub；每轮故障解除后验证开关已恢复，防止污染后续用例。

## 7. 准入、缺陷与回退验收

### 7.1 发布准入

- ODR-01～ODR-16 均有对应执行证据；全部 P0 和适用 P1 通过。
- 两个核心失败案例通过：A 抓取失败、B 成功后 A 不改版本仍能重试；删除失败后仍能在下一轮重试。
- 不完整扫描、权限异常、选中集合间移动均没有误删；关闭删除后再开启能够重新确认。
- 密钥、正文与敏感响应没有出现在日志、游标、普通 API 响应或测试报告中。
- 真实自托管固定版本完成基础端点、Markdown 包装、软删除与 404 错误契约测试。
- 标准模式、单实例 Lite、迁移和回退通过，万篇级结果满足第 5 节。
- 解析与检索端到端完成：唯一测试短语命中预期文档及版本，越权成员无法命中。
- 未执行、阻塞或版本未固定的用例不得以“静态代码看起来正确”替代。

### 7.2 缺陷分级

| 严重级别 | 示例 | 处置 |
| --- | --- | --- |
| S0 | 越租户访问、Token 泄漏、批量误删 | 立即停止发布，保留证据并恢复测试环境；必须修复后重测 |
| S1 | 失败版本永久跳过、同正文合并身份、断点无法恢复、主要流程不可用 | 阻断发布，补最小复现和回归用例 |

首期已知设计边界不是新增缺陷：无用户 ACL 映射、私有附件不本地化、更新存在替换窗口、普通增量不保证恢复手动删除副本、单实例 Lite、API 列表可能传全文。若界面错误宣传这些能力，按对应需求缺陷处理。
