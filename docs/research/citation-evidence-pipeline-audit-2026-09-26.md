# 引用证据链审计与本轮修复

日期：2026-09-26。范围：解析图片、资源存储、图片任务、父子分块、检索扩展、模型上下文、引用与 DOCX 预览。基于本地实际 query、数据库分块、原始 DOCX 和浏览器点击验证。用户文档和原文内容仅保留在被 Git 忽略的本地回放目录。

## 结论

存在多个独立问题，不能归结为 AnyDoc 转 Markdown 或一个高亮算法错误。

本次 DOCX 的实际 query 使用 Agent `search_knowledge`，未经过普通问答的父块合并。回答里的明确引文位于另一个子块，模型却引用了开头子块。普通问答的父块扩展另有相同表象的结构缺陷：扩展后内容仍使用原子块 ID，两者必须分别处理。

样本分块统计：19 个 text（其中 6 个无位置，主要是连续图片）、2 个 parent_text、47 个 image_caption、45 个 image_ocr。92 个图片派生块均无 source_locators。OCR 和 caption 数量不同本身不等于失败，图片可以没有可识别文字。

## 已修复并验证

| 环节 | 原问题 | 本轮处理 |
| --- | --- | --- |
| 图片归属 | URL 子串匹配；未命中时挂到文档第一个块 | 使用完整 Markdown/HTML 图片目标；无匹配或多个不同块匹配时不伪造父块 |
| 图片身份 | 只有资源 URL、OCR、caption，无可在 DOCX 原文核验的图片身份 | 新图片派生块记录原始图片字节 SHA-256；旧块可经知识库鉴权代理读取图片计算指纹 |
| DOCX 图片定位 | 相邻图片无前后文字锚点，无法定位；序号猜测会错位 | 比对 docx-preview 内嵌图片字节指纹，只接受唯一匹配，标注图片区域；重复图片拒绝任选第一张 |
| 图片读取失败 | 记录 skipped 后返回 nil，任务被当作成功 | 返回带原始 cause 的错误，交由任务重试；耗尽重试时记录失败 |
| 普通问答上下文 | 合并、邻块扩展、父块扩展的整段正文挂在某个子块 ID 下 | 保留用于排名的合并结果；生成模型上下文前重新装配实际源块，每块拥有自己的 ID、正文、类型和位置；不混入禁用或其他文档块；无法核验的扩展结果不作为证据 |
| 模型引用规则 | 模型可能用同文档第一个 cN 支撑后文内容；把图片水印当正式承诺 | 明确要求逐块核验引文、使用真正含引文的 cN；图片水印与图片描述须按其证据性质使用。这是生成约束，不是语义正确率保证 |
| 文字高亮 | 改写后的回答整句不等于原文，回退为整个子块高亮 | 提取回答中的明确引文，仅在引用证据中唯一逐字匹配时缩小范围；数字条件不放宽 |
| 历史错引 | 点击开头子块，但明确引文实际在其父块后文 | 只在同文档、未编辑、有精确来源映射及源文件哈希的直接父块中恢复引文，再核验原文中的唯一位置；不进行全文件模糊搜索 |

真实回放确认：图片跳到原始 DOCX 中对应照片（字节相同），不是旁边的电梯照片。后文引文只高亮其实际短句，文档开头不再被整段高亮。此兼容处理不改写历史回答的原始 chunk ID，历史悬浮摘要仍可能显示旧块。

## 尚需继续改造的缺口

1. **图片索引失败被吞掉（高优先级）**：`image_multimodal.go:indexChunks` 多个分支只写日志后返回，调用处仍写 `indexed=true`。需要返回结构化索引结果，串联分块 index_status、图片 span 与文档完成状态。当前没有将这项标记为已修复。
2. **任务重试幂等性（高优先级）**：图片派生块使用随机 UUID。持久化成功后若发生后续失败，重试可能重复写入。修复索引重试前，需要以文档版本/解析 attempt/图片身份/块类型建立幂等键，复用已持久化内容，再重试索引；不能只把索引错误向上抛出。
3. **OCR 字词坐标缺失**：指纹可准确定位照片，但图片内某一行文字需要 OCR 的字词框。当前 caption/整图 OCR 不具备这一契约，因此界面仍显示“来源区域”，不会宣称文字级精确。
4. **图片多次出现的归属**：资产身份不等于出现位置。同一字节图片重复出现时仍需 occurrence ID、DOCX relationship + block 或 PDF page + bbox。当前明确拒绝含糊匹配，尚未给每次出现建立独立关系。
5. **模型引用的语义校验**：提示词不能保证 cN 一定选对。下一步应要求模型返回可验证的原文摘录/证据 ID，服务端对照本轮可访问源块核验；图片 caption、OCR、水印、正文分别标注证据类型。完全改写、综合多个来源的陈述还需单独评估，不宜用低阈值相似度假装精确。
6. **生成问题可能偏离子块**：实际样本开头子块的生成问题涉及其正文以外的服务保障内容。现有提示已要求 surrounding_context 只辅助理解，但缺少输出约束/评估；它会影响召回相关性。这是观察到的样本问题，尚无全库发生率统计。
7. **旧数据与重编码**：旧块的图片身份需临时读取资源；若外部解析器重新编码图片，字节指纹不能跨编码匹配。应在提取时记录原始资产身份及位置，避免用视觉相似图冒充同一来源。新的 sha256 字段无需数据库迁移，但历史持久化补齐尚未进行。

## 建议的数据契约

- 文件版本：原文件 hash + 解析 attempt。
- 原文单元：稳定 source unit ID、类型、原文摘录、页/块/框、图片 occurrence ID。
- 检索块：可组合多个原文单元，但不替代原文单元身份。
- 模型上下文：背景上下文与可引用证据分开，每条证据有独立句柄。
- 回答引用：句柄 + 可验证摘录；后台验证后再提供精确位置。
- 状态：解析成功、图片识别成功、索引成功分别记录，不能用一个完成状态掩盖部分失败。

## 2026-09-27：Markdown Git 分支占用问答回归

### 根因

最近的本地 query 引用了正确的 Markdown 子块。该文件较短，子块与父块都是整篇正文（仅尾部换行不同），因此本例没有父块替换成错误来源的问题。

1. 定位把 Markdown 源码清洗后直接与预览 DOM 比较。源码里的 fenced code 语言 `bash` 仍参与匹配，而预览只显示命令，导致全文匹配失败。
2. 引用在“原理”段末，前端只取最后一句作为定位上下文，丢失前面的 `--detach` 原理。
3. 通用 HTML 清洗还会误删代码里的字面量标签，因此 Markdown 需要保留未清洗源码。

### 修复与边界

- 引用请求单独传递 `sourceMarkdown`；通过预览相同的渲染器和消毒器，在 inert template 中得到可见文本。
- 先唯一核验完整来源范围，再在其中匹配摘录或选择有明确文字重合的段落；完整来源缺失或重复时拒绝定位，不以局部相似句绕过校验。
- 段末引用保留从前一个引用之后的完整段落，最多 300 字；改写可以对应多个原文段落。
- 本例实际高亮“理解”和“提醒”两条，排除“场景”“做法”和代码块。改写的段落选择标记为 block，不声称逐字匹配。
- 本修复不改变检索分块、不重新解析文件，也不补齐前文列出的图片索引及服务端引用语义校验缺口。跨语义改写的段落选择仍不是语义正确率保证。

### 验证

- 76 项引用/定位/Markdown 渲染 Node 测试通过；前端类型检查和生产构建通过。
- 45/45 浏览器生成样本通过，包含新增的 Markdown 和 DOM 引用锚点用例。
- 18/18 私有原文件回放通过；新增真实 Git 问答，断言两条原文的高亮文本完全符合预期。
- 实际会话点击引用，截图核验只高亮目标两条。历史会话刷新即可使用，无需重新上传。

## 2026-09-27：README 引用只高亮域名前缀

真实引用子块在 `App 只对 api.github.com` 后结束，后面的只读请求、钥匙串和 iCloud 说明属于同一原文段落，却在子块边界外。之前根据子块重新渲染得到的“段落”进行缩小，误将分块末尾残句当成完整原文段落。父块仍包含完整说明；此处是检索块边界被当成阅读边界的问题。

修复：完整来源唯一匹配后，从原文 DOM 获取与该范围相交的段落，用实际原文段落边界展示上下文。候选必须与核验范围至少重叠 8 个规范化字符；不搜索相似的相邻段落，不靠补全挽救缺失或重复的来源。段落上下文可能包含子块以外的文字，因此仍标记为 block，不声称原回答逐字覆盖完整段落，也不改写历史引用 ID。明确的逐字摘录仍优先保持精确范围。

验证：52/52 浏览器回归、19/19 私有原文件回放通过，新增真实 README 用例断言完整段落的高亮文本；76 项 Node 测试、类型检查和生产构建通过。实际会话截图确认段落完整且没有延伸到后续联网同步段落。

这项修复作用于阅读定位。分块仍可能切开长段落；可引用证据单元与检索块分离、服务端核验模型引文等后续缺口仍以本报告前述清单为准。
