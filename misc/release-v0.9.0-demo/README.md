# v0.9.0 发布演示资料

「周末读书会」资料完全虚构，专用于发布截图与功能实测。日期、人数、流程和筹备安排均为演示设定，不含真实联系人、用户文件或业务数据。

## 输入与使用范围

- [活动介绍](活动介绍.md)、[报名须知](报名须知.md)、[筹备安排](筹备安排.md)。
- 截图使用 demo 账号，只展示本轮虚构知识库、派生资料和操作结果，收起历史对话。
- 演示环境与发布基线不同，仅展示已进入发布基线的功能。截图不是固定发布构建的验收证据。

## 实测与截图

2026-10-28 完成三份资料的上传和解析；通过助手创建智能体、派生文档与知识卡片，并核对保存结果。只读模式的写入被拒绝；写入使用单次审批，未开启后续同类操作自动允许。

| 素材 | 内容与验证 |
| --- | --- |
| `assistant-release-guide` | 提问「WeKnora v0.9.0 有哪些新功能？我可以从哪里开始使用？」；演示构建载入本次发布文档，助手实际查询后回答新增能力、使用入口与参考链接，不限制回答字数 |
| `assistant-overview` | 读取当前知识库，为首次主持读书会的人整理活动前、中、后的筹备建议，并附来源 |
| `agent-collaboration` | 三个子任务分别读取活动、报名和筹备资料；核对独立任务输出与主任务汇总 |
| `assistant-permissions` | 审批将「报名常见问题」改为「读书会报名问答」；单次批准后确认名称变化，正文不变 |
| `automation-setup` | 手动设置每天 09:00、Asia/Shanghai，并展示后续运行预览 |
| `automation-conversation` | 通过对话调整现有任务的时间、资料范围、会话方式与通知；手动运行后核对待办与来源 |

自动化保持暂停，未开启后续定时运行。测试中出现模型重复调用、协作请求缺少 `task_name` 和自动化请求缺少 `type` 的情况，明确需求或补齐参数后完成；这些重试路径仍需在固定发布构建上复测。本轮未修改产品运行代码，也不将本地耗时作为性能基准。
