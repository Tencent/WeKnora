# RHINO-EMBED-STRICT-2026 索引重建验收

本文档用于验证 WeKnora 的 embedding 持久化缓存。冷批次与暖批次正文必须逐字一致，只有文件名不同。实验不得清理缓存、知识库或历史调用记录，而是通过时间窗口区分两次索引处理。

## 可复现配置

实验固定使用同一个租户、同一个知识库配置、同一个 embedding 模型和同一组分块参数。上传冷批次前记录开始时间；文档处理完成后记录结束时间。随后上传暖批次并记录第二个独立时间窗口。

## 冷批次预期

第一次处理这段新文本时，缓存中不存在对应的模型与文本组合。系统应记录缓存查询和未命中事件，并调用底层 embedding Provider 生成向量。Provider 调用次数应大于零。

## 暖批次预期

第二次处理逐字相同的正文时，系统应复用第一次保存的向量。缓存命中数和避免计算数应增加，底层 embedding Provider 调用次数应明显低于冷批次。

## 统计口径

请求文本数表示索引流水线尝试向量化的文本数量。Provider 调用数表示缓存未能满足请求、必须执行实际模型计算的文本数量。避免计算数等于缓存命中和并发去重所节省的计算数量。

## 隔离与隐私

缓存键包含租户和模型命名空间，不能跨租户复用。持久化层只保存向量计算所需的键和值以及过期时间；模型调用观测不保存提示词正文、模型回答或 API Key。

## 验收判定

若暖批次的请求文本数与冷批次相当，同时 Provider 调用数下降且避免计算数增加，则 embedding 缓存优化通过。若命中没有增加，报告必须保留原始结果并说明模型、文本规范化或分块配置是否发生变化。

## 结果解释

缓存改善主要减少重复模型计算和外部请求。总耗时还会受到文档解析、数据库写入、向量存储和任务队列影响，因此不应仅凭一次总耗时变化宣称性能一定提升。
