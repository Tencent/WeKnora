# RAG 双模型受控对比与重复实验摘要

## 实验目的

本实验验证评测系统能否在固定数据集、知识库来源、分块、检索管线和依赖模型的前提下，
比较不同对话模型的检索质量、生成质量、端到端耗时、Token、缓存遥测与估算费用。
它用于证明评测闭环和可解释的取舍，不用于宣称某个模型在更大范围内绝对更优。

## 可比性与原始证据

两次代表性运行均使用 `rhino-topic3-zh` 的 4 个问答样本：

- 数据集指纹：`sha256:f492c72ee32d288b46b8f74891d03e53f507e2e4842c254ebc98a3e4ced44bed`
- 受控配置指纹：`sha256:a607d2d3c8a8725d6afa77fb9b999e64a9c32238d0bb6e21a073a86b1dbf1802`
- Embedding：本地 `nomic-embed-text:latest`，768 维
- 唯一变化变量：对话模型

服务器导出的两份原始 JSON 均通过 `cmd/evidenceverify` 校验：

| 对话模型 | 原始报告 SHA-256 |
| --- | --- |
| 百炼 `qwen3.7-plus` | `sha256:f339e386b2a5364bccb805113c7bcd9c3e2484605bcc1a9f9abf509720e500b8` |
| 本地 `qwen2:7b` | `sha256:40c08d1d430a681d04a620fb88b509b7a25d3982ec47854e522eef5aa4f63d1e` |

原始报告保留在实验操作者本地，未直接提交到公开仓库，因为其中包含租户编号以及知识库、
模型和 Chunk 的内部 UUID。本报告仅公开指标、非敏感指纹和原始报告校验和；没有 Prompt、
问题、参考答案、模型回答或检索正文。

实验发生在最终同步腾讯上游之前，导出报告记录的构建版本前缀为 `e8b17722`；同步后对应的
功能提交为 `340e9e98`（`feat(evaluation): aggregate repeated run statistics`）。最终分支又包含了
后续证据、严格 Wiki A/B 和文档修正，因此复验应以最终 Tag 为准，而不把旧运行冒充成最终
提交上的重新执行结果。

## 重复实验摘要

界面只聚合代码、数据、配置、知识库、模型指纹和调用工作负载完全一致的成功运行。
百炼 `qwen3.7-plus` 的 3 次匹配运行显示：

| 指标 | 汇总值 |
| --- | ---: |
| Recall 中位数 | 100.00% |
| 耗时中位数 | 12.76 s |
| 耗时 P95 | 13.40 s |
| Token 中位数 | 6,092 |
| 缓存命中率中位数 | 0.00% |
| 成本中位数 | 0.024376 CNY |

该重复汇总来自数据库中的三次严格匹配运行；上表两模型对比则来自各自一份通过校验的代表性
导出。两种统计口径被明确分开，没有用单次最好结果替代中位数，也没有把不匹配运行混入聚合。

## 结果边界

- 数据集只有 4 个样本，适合验收可复现机制，不足以形成通用模型排行榜。
- BLEU/ROUGE 衡量与单一参考答案的词面重合，不等同于完整事实正确性或用户偏好。
- 远程服务和本地硬件的耗时不构成同等算力条件下的纯模型速度比较。
- 本地模型没有价格与缓存遥测时保持未知值；不从缺失数据反推零费用或零命中。
- 最终提交同步上游后没有重跑这组付费实验，因此保留旧构建版本信息并明确披露。
