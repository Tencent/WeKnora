# Wiki 缓存真实测量：阿里云百炼 qwen3.7-plus

本报告记录 2026-08-30（北京时间）在本地 WeKnora 上执行的真实 Provider 实验。原始结构化结果见 `wiki-cache-bailian-2026-08-30.json`。实验未导出 Prompt、模型回答、API Key 或租户标识，知识库、文档、Wiki 页面和数据库记录均被保留。

## 固定配置

- Provider：阿里云百炼，华北2（北京）
- 模型：`qwen3.7-plus`
- 知识库：`Topic 3 Wiki Cache Acceptance`
- 调用用途：`wiki_page_modify`
- 输入：两份固定 Markdown 文档，SHA-256 已写入 JSON
- 价格快照：输入 2 CNY/M、输出 8 CNY/M、缓存读取 0.4 CNY/M、隐式缓存写入 0
- 数据来源：PostgreSQL `evaluation_model_calls`

## 结果

| 指标 | 冷调用（未命中） | 暖调用（真实命中） |
| --- | ---: | ---: |
| 调用数 | 4 | 6 |
| Prompt Token | 10,620 | 16,411 |
| 缓存读取 Token | 0 | 6,528 |
| 缓存未命中 Token | 10,620 | 9,883 |
| Token 缓存命中率 | 0% | 39.78% |
| 单次最高命中率 | 0% | 62.98% |
| 每千 Prompt Token 估算输入成本 | 0.002 CNY | 0.0013635 CNY |
| 平均耗时 | 6,058 ms | 9,025 ms |

缓存读取 Token 由百炼响应中的缓存用量字段返回，并由 WeKnora 写入数据库，不是根据请求相似度推断。按相同 Prompt Token 口径，估算输入成本下降约 31.8%。包含输出成本后，每千 Prompt Token 的完整估算费用下降约 2.9%，因为暖调用组生成了更多输出 Token。

本轮延迟没有改善：暖调用平均耗时增加 2,967 ms，并包含一次 20.9 秒长尾调用。因此本报告只得出“缓存命中率和归一化输入成本改善”的结论，不宣称延迟改善。

## 产物与质量观察

两份文档的解析和摘要状态均为 `completed`，共生成并发布 13 个 Wiki 页面。页面中存在两个标题同为 `RhinoCache` 的实体页，说明并行生成的页面去重仍有可改进空间。该观察不影响缓存字段真实性，相关记录没有被删除。

## 结论边界

冷调用与暖调用来自同一批文档的连续 Wiki 操作，但不是逐字节相同的请求，因此它们是线上运行对比而非严格 A/B 回放。真实账单可能因新人免费额度而为零；报告中的费用是按配置的公开原价计算，用于比较优化效果。
