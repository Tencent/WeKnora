# Wiki 缓存真实测量：阿里云百炼 qwen3.7-plus

> **成本勘误（2026-09-09）：** 本轮把隐式缓存创建价格配置为 0，但百炼的隐式缓存创建 Token 实际按普通输入价格计费。原始 JSON 和数据库记录继续保留以保证证据可追溯；下文的缓存 Token、命中率和耗时仍可复核，但所有费用及“成本改善”结论均不得作为最终验收证据。最终成本结论应使用价格快照为 `2 / 8 / 0.4 / 2 CNY/M` 的新严格 A/B 报告。

本报告记录 2026-08-30（北京时间）在本地 WeKnora 上执行的真实 Provider 实验。原始结构化结果见 `wiki-cache-bailian-2026-08-30.json`。实验未导出 Prompt、模型回答、API Key 或租户标识，知识库、文档、Wiki 页面和数据库记录均被保留。

## 固定配置

- Provider：阿里云百炼，华北2（北京）
- 模型：`qwen3.7-plus`
- 知识库：`Topic 3 Wiki Cache Acceptance`
- 调用用途：`wiki_page_modify`
- 输入：两份固定 Markdown 文档，SHA-256 已写入 JSON
- 当时配置的价格快照：输入 2 CNY/M、输出 8 CNY/M、缓存读取 0.4 CNY/M、隐式缓存创建 0（该配置后来确认错误，费用结果作废）
- 数据来源：PostgreSQL `evaluation_model_calls`

缓存读取 Token 由百炼响应中的缓存用量字段返回，并由 WeKnora 写入数据库，不是根据请求相似度推断。原报告曾按错误的缓存创建价格得出输入成本下降约 31.8%、完整估算费用下降约 2.9%；这两个费用结论现已作废，仅保留文字用于说明勘误来源。

本轮延迟没有改善：暖调用平均耗时增加 2,967 ms，并包含一次 20.9 秒长尾调用。因此本报告只能证明 Provider 返回了缓存命中，不能证明成本或延迟改善。

## 产物与质量观察

两份文档的解析和摘要状态均为 `completed`，共生成并发布 13 个 Wiki 页面。页面中存在两个标题同为 `RhinoCache` 的实体页，说明并行生成的页面去重仍有可改进空间。该观察不影响缓存字段真实性，相关记录没有被删除。

## 结论边界

冷调用与暖调用来自同一批文档的连续 Wiki 操作，但不是逐字节相同的请求，因此它们是线上运行对比而非严格 A/B 回放。真实账单可能因新人免费额度而为零；本报告的费用价格快照配置错误，不得用于比较优化效果。
