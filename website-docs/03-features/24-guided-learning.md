# 引导式学习使用手册

引导式学习在 Wiki 中推荐主题、生成带来源的三题练习，并根据本人提交的答案记录掌握度与复习状态。本手册按首次启动、准备资料、练习、Agent 和数据管理的顺序操作；完成后应能提交一组测验、核对来源并导出个人记录。

- 已有运行实例和 Wiki：从[练习流程](#练习流程)开始。
- 首次使用：按[从源码启动](#从源码启动)、[准备知识库](#准备知识库)顺序操作。
- 希望直接使用合成数据，或执行完整验收：见[测试手册](../06-development/04-guided-learning-testing.md)。

## 适用范围

本版本支持已登录 Web 用户，以及当前工作空间自有且启用 Wiki 的知识库。共享知识库、共享 Agent、API Key、IM 和嵌入式客户端不在支持范围内。普通学习操作不要求系统管理员；建库、配置模型和内置 Agent 需相应空间权限，首次可用自己创建的空间 Owner 账号体验。

只体验 Wiki 学习，需要一个可用的对话模型；使用 Agent 时该模型还需支持 Tool Calling。不需要先部署 Neo4j、开长期记忆或配置 Embedding。下文建库时会关闭 RAG 索引；若同时使用向量或关键词检索，则需按[模型管理](06-models.md)配置 Embedding。

## 从源码启动

已有包含学习功能的实例可跳过本节。以下为 Linux/macOS 的独立开发环境，需要 Docker Compose、Go 1.26、CGO 编译工具和 Node.js 24；Python 3.10+ 仅在运行测试脚本时需要。

功能尚未合入主线时，应运行 PR 的源码，不能仅拉取官方 `latest` 镜像：

```bash
git clone https://github.com/Tencent/WeKnora.git WeKnora-learning
cd WeKnora-learning
git fetch origin pull/3145/head:pr-3145
git switch pr-3145
git log -1 --oneline
cp .env.example .env
```

只在新建目录执行这些命令，不覆盖已有 `.env`。在 `.env` 中保留 PostgreSQL、Redis、本地文件存储和 `RETRIEVE_DRIVER=postgres`，并确认：

```dotenv
DB_DRIVER=postgres
DB_HOST=127.0.0.1
DB_PORT=5432
STREAM_MANAGER_TYPE=redis
STORAGE_TYPE=local
RETRIEVE_DRIVER=postgres
AUTO_MIGRATE=true
SERVER_HOST=127.0.0.1
SERVER_PORT=8080
LOG_LEVEL=info
LANGFUSE_ENABLED=false
DISABLE_REGISTRATION=false
WEKNORA_AUTH_DEFAULT_TENANT_MODE=create_personal
WEKNORA_TENANT_ENABLE_CROSS_TENANT_ACCESS=false
```

启动前替换示例中的数据库/Redis 口令、`JWT_SECRET`、`SYSTEM_AES_KEY`。可分别用 `openssl rand -hex 32` 和 `openssl rand -hex 16` 生成 JWT 密钥与 32 字符 AES 密钥；私下填写，勿提交到 Git。开发 Compose 会映射基础设施端口，只用于隔离开发机，不要暴露到公网。

在仓库根目录启动依赖：

```bash
make dev-start DEV_ARGS=--no-langfuse
make dev-status
npm --prefix frontend ci
```

应看到 PostgreSQL、Redis 和 docreader 运行。这个流程不需要 MinIO、Qdrant、Neo4j 或 Langfuse。首次构建 docreader 和下载依赖可能较久，失败时先检查 `make dev-logs`。

另开终端，在同一仓库运行后端并保持终端打开：

```bash
make dev-app
```

再开终端启动前端，端口被占用时明确报错：

```bash
VITE_DEV_PROXY_TARGET=http://127.0.0.1:8080 \
  npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

浏览器访问 `http://127.0.0.1:5173`。检查后端与前端代理：

```bash
curl --fail --silent --show-error http://127.0.0.1:8080/health
curl --fail --silent --show-error http://127.0.0.1:5173/api/v1/auth/config
docker compose -f docker-compose.dev.yml exec -T postgres sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT version, dirty FROM schema_migrations;"'
```

预期健康状态为 `ok`，认证配置为 JSON，当前 PR 的 PostgreSQL 迁移版本为 `95` 且 `dirty=false`。健康检查不检查迁移，遇到迁移错误不要手工改版本跳过。SQLite 对应版本为 `16`，本节没有运行 Lite 路线。

若 `8080`/`5173` 已占用，修改 `SERVER_PORT`、前端 `--port` 和代理地址，测试变量也要一致更新。已有 `WeKnora-*-dev` 容器时不要重复启动同名 Compose 或停止他人的环境。其他部署方式见[开发指南](../06-development/01-dev-guide.md)。

远程开发机可在自己电脑建立转发：`ssh -N -L 5173:127.0.0.1:5173 <开发机用户>@<开发机地址>`，再打开本机 `http://127.0.0.1:5173`。结束体验时先在前后端终端按 Ctrl+C，再执行 `make dev-stop`；数据卷保留，不要执行 `clean-db`。

## 准备知识库

### 注册与模型

1. 打开前端并注册账号，然后用邮箱和密码登录。系统没有默认账号。专用实例的默认配置会创建个人空间；团队实例注册关闭时，需先接受邀请。
2. 确认当前空间是自己的空间，而非协作知识库所在的其他空间。
3. 进入「系统设置 → 模型管理 → 添加模型」，配置对话模型的厂商、模型名称、Base URL 和 API Key，测试连接后保存。已有可用模型则跳过。没有编辑权限时请空间 Admin/Owner 配置。

Base URL 使用供应商提供的 API 入口，不填完整 `/chat/completions` 路径。网络连通只代表可访问，模型还需能按题目格式输出并正确调用工具；首次先用短文档验证，避免批量导入产生不必要的费用。

### 新建仅 Wiki 的知识库

1. 在「知识库」点击「新建知识库」，进入「基本信息」，类型选「文档」，名称例如「限流学习」。
2. 在「索引策略」取消勾选「RAG 检索」，勾选「Wiki 知识库」；提取粒度保持「标准」。
3. 在「模型配置」选择「LLM 大语言模型」；本路线的「Embedding 嵌入模型」可留空。「Wiki 合成模型」可选同一对话模型，留空时回退使用 LLM。
4. 点击「创建」，完成后「保存并关闭」。

缺少 Embedding 时创建弹窗可能先展示「模型配置」，仍可切回「基本信息」设置索引策略。已有文档的库会锁定索引策略，首次体验请新建空库，不要尝试把有内容的普通库直接改成 Wiki。

### 上传与检查来源

在新库的「文档」页点击「上传文档」，选择一份短 Markdown，点击「确认上传并解析」。优先使用自己熟悉、包含具体事实的资料，便于人工核对题目。没有资料时，可用下面的内容作为 `rate-limiting.md`：

```markdown
# 接口限流

## 令牌桶
令牌桶按固定速率补充令牌，每个请求消耗一个令牌。
桶容量限制最多可以积攒的令牌数，桶满后新增令牌被丢弃。
没有令牌时，请求被拒绝或等待；允许等待需要另外限制队列长度。
补充速率决定长期平均处理速率，桶容量决定可容忍的突发规模。
例如桶容量为 20、每秒补充 5 个令牌，满桶时可立即接收 20 个请求。

## 固定窗口
固定窗口统计一个固定时间段内的请求数，达到上限后拒绝该窗口内的新请求。
窗口切换时计数清零。相邻窗口交界处的集中请求可能形成短时突发。
例如每分钟上限 100 次，前一分钟末尾与下一分钟开头可能各接收 100 次。

## 滑动窗口与客户端重试
滑动窗口统计从当前时刻向前的一段时间，减少固定窗口边界的突发问题。
精确滑动窗口可以记录请求时间戳，但存储和清理成本随请求量增加。
HTTP 429 表示请求过多；服务端可以用 Retry-After 告知建议重试时间。
客户端应遵守服务端等待提示，并限制重试次数，避免立即密集重试。
```

上传、Wiki 合成和出题都会调用已配置的模型。仅使用获准发送给该模型供应商的资料。

文档处理状态应从排队/处理中进入完成。随后切换「Wiki」，等待目录中出现页面。文档解析完成与 Wiki 合成完成是两件事；尚无页面时查看异步处理进度，稍后刷新，不要重复上传同一文档。

打开例如「令牌桶」这样的概念页，检查正文与引用来源能否打开。标题由模型生成，不保证与示例完全相同。具备以下条件再开始练习：

- 页面已发布，类型为 `entity`、`concept`、`synthesis` 或 `comparison`。
- 关联来源文档已完成解析且启用。
- 引用分块非空、启用且索引状态为 `ready`。

首页 `index`、摘要 `summary` 不出题。有 Wiki 正文但没有有效来源时也不能出题。固定数据初始化与恢复步骤见[测试手册](../06-development/04-guided-learning-testing.md#创建测试数据)。

## 练习流程

### 开启与阅读

1. 在知识库「Wiki」页面顶部找到「引导学习」，开启「个人学习记录」，确认显示「已开启」。
2. 在「推荐练习」选择主题或点击「打开页面」，阅读正文和来源；也可以从 Wiki 目录选择一个可练习页面。
3. 检查页面标题，点击「练习当前页面」。练习针对当前主题，不针对整个知识库。

学习开关属于当前用户、当前空间，对该空间内的自有 Wiki 库生效。长期记忆授权与它独立；已有兴趣和文档亲和度只在记忆相关开关允许时参与推荐。无需先开启「我的记忆」。

### 等待与作答

| 界面状态 | 操作 | 预期结果 |
| --- | --- | --- |
| 测验已排队 / 正在准备测验 | 等待，或点击「停止等待」 | 后台继续生成；停止的只是前端状态检查 |
| 已暂停状态检查 | 点击「再次检查」 | 继续获取原任务状态，不重复创建 |
| 三道四选一题 | 选一项，点击「提交答案」 | 服务端返回正误、正确选项、解析与来源引文 |
| 提交网络失败 | 点击「重新提交」 | 重试原作答，不借此更换选项 |
| 测验准备失败 / 来源已变更 | 核对来源和模型，再「生成新测验」 | 基于当前来源重新准备 |

提交后点击「来源 1」等按钮，对照原文核对答案。三题完成后可点「开始新练习」，本次界面中仍可查看「上次练习」。同一来源版本下重复题干只计分一次，重复点击或重放同一个 attempt 不增加掌握度。

在同一浏览器标签页刷新、重新打开同一页面，可恢复保存的测验及作答。页面用 `sessionStorage` 记住测验 ID；关闭标签页、换浏览器后不保证自动定位上次测验。需要跨次查阅时，可保留 Agent 卡片会话或导出学习记录。

页面、来源内容或生成配置变化会让旧测验过期，不能继续提交；请重新生成。常规页面重命名保留主题标识和历史。

### 图谱中的学习状态

切换「图谱」页签，查看「未评估」「学习中」「已掌握」「待复习」图例和独立的「已接触」标记。这里是 Wiki 页面链接图，不依赖 Neo4j 的实体关系图谱。

点击节点打开详情，可阅读或练习该节点；关闭详情后切回「Wiki」，页面标题与练习对象应保持为选中的主题。移动端入口相同，目录折叠时先展开选择主题，再收起阅读。

## 学习状态

「已接触」表示访问过页面，或多次使用过其来源文档；该状态不能说明答题正确或已经掌握。

练习采用贝叶斯知识追踪（BKT），固定参数为：初始掌握度 0.20、学习转移 0.15、猜对概率 0.25、失误概率 0.10。至少需要三道不同题目的有效作答，且估计值达到 0.85，才会标记为「已掌握」。复习间隔为 1 至 30 天。来源变化后仍保留历史记录，当前掌握度会重置为先验值，等待重新评估。

这些默认参数尚未在真实学习者上校准。显示的概率仅为算法估计，无法证明实际熟练程度。现有 Wiki 链接只用于识别相关主题，不能据此建立先修课程关系。

## Agent 使用

### 配置入口

内置 Agent 没有默认对话模型，首次须由空间 Admin/Owner 配置：

1. 进入「智能体」，点击「引导式学习」卡片，或通过卡片更多菜单选择「编辑」。
2. 在「模型配置 → 模型」选择支持 Tool Calling 的对话模型。
3. 在「知识库 → 关联知识库」选择「指定知识库」，选中当前空间自有、带 Wiki 标记的「限流学习」，点击「保存并关闭」。不要选协作知识库。
4. 进入「新对话」，选择「引导式学习」，确认使用刚才的知识库。

Agent 对话模型与知识库出题模型是两处配置。出题仍使用知识库的「Wiki 合成模型」，未设置时使用其 LLM/摘要模型；只配置 Agent 模型不能补齐知识库配置。

### 一次完整对话

在 Wiki 中开启个人学习记录后，依次发送：

```text
查看我在这个知识库的学习概览，推荐一个有来源依据、适合现在练习的主题，并说明推荐原因。
```

```text
请读取刚才推荐的 Wiki 页面，并为这个主题准备练习测验。不要替我作答。
```

展开「学习概览」「推荐练习」或「准备练习测验」的工具结果，打开页面或测验卡片。选择答案后在卡片内点击「提交答案」，查看来源反馈；重新加载该会话后，卡片应读取已保存结果。

模型不一定每次都按相同顺序调用工具。只输出文字不能算测验已经生成，应看到可打开的工具卡片。Agent 无权替用户授权、答题或修改掌握度；未开启学习时需回到 Wiki 面板手动开启。

## 隐私

### 导出与清除

打开「引导学习 → 学习数据」：

| 菜单 | 范围与结果 |
| --- | --- |
| 导出当前知识库（JSON） | 下载本人的当前库学习记录，文件名为 `guided-learning.json` |
| 导出全部学习数据（JSON） | 导出本人在当前空间的学习数据，不包括其他用户或空间 |
| 清除当前知识库记录 | 删除该库个人题集、作答和主题状态，不删除源文档与 Wiki |
| 清除全部学习数据 | 删除本人在当前空间的全部学习数据，并关闭个人学习记录 |

清除不可撤销。需保留记录时先导出；确认弹窗点「取消」不会删除，点「永久删除」才执行。完成后显示删除的作答、主题记录和测验数量。删除验收只在一次性账号上进行。

清除单个库保留其他库历史，但会使本人其他库的活动测验过期；若已无剩余主题记录或题集，也会关闭学习授权。学习清除不删除长期记忆，后者在「我的记忆」中独立管理。

### 关闭与来源变更

关闭「个人学习记录」保留历史，使当前空间本人的活动测验过期；重新开启后需生成新测验。关闭后仍可导出或删除，不能把关闭当作删除历史。

来源文档被删除、移出当前范围后，相关测验和已保存答案会一并删除；多来源 Wiki 页面继续存在时也执行该规则。导出会立即执行清理，后台恢复流程也会处理。之后基于保留来源完成的评估不会被删除。

生成题目时，系统只向已配置的模型供应商发送有长度限制的 Wiki 和来源文本，不发送用户兴趣、个人档案或历史答案。答案保存在服务端，不进入常规模型或请求诊断，也不写入 Agent 对话记录。导出文件不会包含未作答题目的答案。

## 常见问题

| 现象 | 检查与操作 |
| --- | --- |
| 找不到「引导学习」 | 确认前后端都包含此功能；使用登录后的自有 Wiki 库 |
| 缺少 Embedding 无法保存 | 仅 Wiki 路线先取消「RAG 检索」；需要检索则配置 Embedding |
| 上传完成但 Wiki 为空 | 合成仍可能运行；检查任务、模型和后端日志，勿重复上传 |
| 没有「练习当前页面」 | 先选实体/概念/综合/对比页；首页和摘要不能练习 |
| 「经验证的来源证据不足」 | 查看文档及分块是否完成、启用且非空；补充真实来源后再试 |
| 一直排队或准备失败 | 检查 worker、Redis、出题模型额度与连接；刷新不能修复后端故障 |
| 「来源已变更」 | 点击「生成新测验」，不继续提交旧题 |
| 提交冲突 | 刷新查看已保存结果；同一道题不能反复更换答案 |
| 阅读很多仍未掌握 | 阅读只增加熟悉度，掌握度需要不同题目的有效作答 |
| Agent 没有卡片 | 检查工具调用支持、库范围和本人授权；展开工具错误查看原因 |
| 403 / 404 | 核对账号、空间、学习开关和库归属；已删除或他人的题集不可访问 |
| 429 | 服务或导出限流，稍后重试，避免连续点击 |

排查时记录操作时间、错误码和请求的 `X-Request-ID`，不要粘贴密钥、账号文件或完整导出。开发者可按[测试手册](../06-development/04-guided-learning-testing.md)复现，不应清空业务数据。

## 使用限制

来源引文校验和同一模型的新对话盲答可以减少错误，不能替代人工审核。对答案有疑问时，应回到来源文档核对。合成测试不代表真人学习效果，当前参数也未证明具有普遍预测优势。

完整接口、权限和错误码见[引导式学习 API](../04-api/02-api-learning.md)。
