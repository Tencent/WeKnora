# RAG 效果调优手册：从问题样本到可验证改进

RAG 调优最容易陷入「换模型、改 Prompt、调阈值」的随机试错。更稳妥的方法是先判断问题发生在**解析、分块、召回、重排还是生成**，每次只改变一个变量，并用固定问题集验证收益。

本文面向知识库产品负责人和 AI Builder，提供一套不依赖特定行业的最小闭环。具体配置与实现细节请配合阅读[分块机制](./04-chunking.md)、[检索引擎](./05-retrieval-engines.md)和[评估功能](./15-evaluation.md)。

## 1. 先定义「变好」是什么

至少同时观察四类指标，避免只优化答案观感：

| 维度 | 推荐问题 | 最小验收信号 |
| --- | --- | --- |
| 事实正确性 | 答案是否与资料一致？ | 关键事实无冲突 |
| 可溯源性 | 引用是否真的支持对应结论？ | 引用块包含答案依据 |
| 覆盖率 | 应答的问题是否都能找到依据？ | 核心场景无明显漏答 |
| 体验与成本 | 延迟、Token 和模型调用是否可接受？ | P95 延迟与单次成本在预算内 |

先写清业务红线。例如客服知识库可以允许「资料不足时拒答」，但不能编造退款规则；内部搜索可以牺牲少量延迟换取更高召回。红线不同，后续参数方向也不同。

## 2. 建立一个最小评测集

第一轮不需要数千条数据。建议从 30～50 个真实问题开始，并覆盖以下类型：

1. **直接事实题**：答案完整出现在一个段落中；
2. **跨段落题**：需要同一文档的两处信息；
3. **多文档题**：需要比较或汇总多个来源；
4. **表达差异题**：用户用词与原文关键词不同；
5. **不可回答题**：资料中没有答案，应拒答或明确说明不足。

每条样本至少记录：问题、期望答案要点、应命中的文档/分块、是否应回答、业务重要度。优先从线上失败对话补充样本，而不是只让模型合成「容易答对」的问题。

::: tip 评测集要版本化
知识内容、Embedding 模型、分块方式或 Prompt 变化后，都用同一批样本回归。新增线上坏例时保留旧样本，才能判断修复是否引入退化。
:::

## 3. 用证据定位故障层

先检查召回到的分块，再看最终答案。下面的顺序可以减少无效调参：

| 现象 | 先检查什么 | 常见原因 | 优先动作 |
| --- | --- | --- | --- |
| 原文存在，候选分块完全没有 | 解析结果、分块预览、索引状态 | 文件解析失败；块边界不合理；索引未完成 | 修复内容管线，重新解析/建索引 |
| 候选里有正确块，但排名很低 | 向量与关键词两路结果、查询措辞 | 语义与关键词权重不匹配；候选数不足 | 扩大候选后观察重排，不先改 Prompt |
| 正确块排名靠前，但答案遗漏 | 送入模型的上下文与回答约束 | 上下文截断；Prompt 未要求覆盖要点 | 调整上下文预算或回答 Prompt |
| 答案正确但引用不支持结论 | 引用块与答案句的对应关系 | 模型利用了常识或引用粒度过大 | 强化基于证据回答；改善分块边界 |
| 不可回答题仍然自信作答 | 召回分数、拒答样本 | 阈值过低；缺少拒答规则 | 加入负样本，校准阈值和拒答策略 |
| 同义问法表现差异大 | 不同问法的召回列表 | Embedding 匹配弱；查询缺少改写 | 先扩充表达差异样本，再评估查询改写 |

一个实用判断：**正确证据没有进入候选集，是检索前半段问题；证据已经进入上下文但答案仍错，才优先看生成阶段。**

## 4. 按固定顺序做单变量实验

### 4.1 内容与解析

- 随机抽查 PDF 表格、扫描件、标题层级和列表是否被正确解析；
- 确认知识处理已完成，异常文档没有停在解析或索引阶段；
- 对图片和扫描件，确认 OCR/多模态结果确实包含答案文字。

如果原始内容在解析后已经丢失，后续更换检索模型不会恢复它。

### 4.2 分块

使用分块预览观察失败样本附近的边界：

- 答案被切到两个块时，优先保留标题语境或适度增加重叠；
- 单块混入多个无关主题时，缩小块或改善标题/段落结构；
- 表格缺少表头时，检查表头追踪与源文档结构；
- 跨段落问题较多时，再评估父子分块，而不是一开始就增大所有块。

分块变化会影响索引内容，应在重建后重新跑完整评测集。

### 4.3 召回与融合

分别观察向量和关键词结果：专有名词、编号、错误码通常受益于关键词检索；同义表达和自然语言问题通常更依赖向量检索。混合检索由上层 RRF 融合，不能直接把不同引擎的原始分数当成同一量纲比较。

先提高候选覆盖率，再收紧最终结果。候选过少时，重排模型没有机会找回正确证据；候选过多则会增加延迟和噪声，需要用评测数据找到拐点。

### 4.4 重排与生成

只有当正确分块已经进入候选集，才评估重排模型。比较启用前后的 Top-N 命中率、延迟和成本，而不是只看一个演示问题。

生成阶段建议明确三件事：只依据给定资料回答、证据不足时如何表达、引用如何对应结论。Prompt 改动同样要回归不可回答题，防止答案更流畅但幻觉更多。

## 5. 一次实验的记录模板

```text
假设：跨段落问题漏答，原因是答案被切散且缺少章节语境。
变更：仅开启/调整父子分块；模型、检索候选数和 Prompt 不变。
样本：评测集 v3，共 42 条，其中跨段落题 10 条。
结果：跨段落命中 6/10 → 9/10；整体正确率 31/42 → 34/42；P95 +180ms。
回归：不可回答题无变化；直接事实题退化 1 条，已记录原因。
决策：接受变更，并把退化样本加入下一轮分块实验。
```

每次实验保留配置快照、评测集版本和失败样本。没有这些信息，就很难区分真实收益、模型波动和知识内容变化。

## 6. 上线前检查清单

- 评测集包含高频、长尾、不可回答和业务红线问题；
- 正确性、引用、拒答、延迟和成本均有基线对比；
- 只改变了可解释的一组变量，并记录了配置；
- 分块或 Embedding 变化后已完成所需的重新索引；
- 为线上失败对话建立了回流和人工复核机制；
- 准备了回滚配置，而不是在生产环境继续试参数。

RAG 质量不是一次性调到最高的参数，而是「真实坏例 → 定位故障层 → 单变量实验 → 固定集回归 → 线上回流」的持续产品闭环。
