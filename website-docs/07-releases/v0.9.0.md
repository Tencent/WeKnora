# v0.9.0 版本说明

发布日期：2026-10-29

v0.9.0 新增 WeKnora 工作助手：解答 WeKnora 的版本、功能与配置问题，结合当前页面，以你的身份创建智能体、设置定时任务、整理知识和调整配置。复杂工作可以拆给多个智能体并行处理。你可以选择只读、修改前确认或自动执行，并逐项处理需要审批的操作。本次更新还完善了沙箱复用、文档解析、数据源同步与检索。

从 v0.8.3 升级前，请阅读[升级须知](#upgrade-notes)。完整变更见 [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md)。

## WeKnora 工作助手：解答产品问题，也处理实际任务 {#assistant}

点击左上角 Logo 旁的新入口，右侧展开 WeKnora 助手。可以询问版本更新、功能用法、配置与故障排查问题；也可以结合正在查看的智能体、知识库、文档或设置页面，创建智能体、安排定时任务、整理资料或调整配置。助手以当前用户身份执行，遵循你的资源权限。

升级后会出现一次入口引导，帮助你找到 Logo 旁的助手按钮；新用户也会在首次使用引导中看到这个入口。

<Screenshot src="/screenshots/assistant-release-guide.png" caption="询问 WeKnora v0.9.0 的新功能，查看产品文档中的使用说明" />

<Screenshot src="/screenshots/assistant-overview.png" caption="结合当前知识库，处理活动筹备中的实际问题" />

- **产品问答**：查询产品文档，了解版本变化、功能用法、配置和排查步骤。
- **用户身份**：使用当前用户身份执行，能够访问和修改的范围由你的权限决定。
- **创建与配置**：创建智能体、选择模型与知识库，或把重复工作设置为定时任务。
- **页面上下文**：理解当前查看的资源，辅助打开页面与填写配置。
- **独立历史**：助手会话单独保存，方便继续处理未完成的事。

当前页面帮助理解上下文，不会自动限制全部检索范围；通过 `@` 可以明确选择本轮使用的资料。详见 [WeKnora 助手](../03-features/26-weknora-assistant.md)。

## 多智能体协作：同时处理多个子任务 {#collaboration}

将研究、分析或整理任务拆成多个独立部分，交给不同智能体处理。主任务汇总结果，子任务的状态和输出可以追踪，遇到待审批事项时由你继续处理。

<Screenshot src="/screenshots/agent-collaboration.png" caption="多智能体协作：查看各个子任务的进度和结果" />

支持临时协作智能体，也可使用同一空间中已有的智能推理智能体作为模板。子任务有独立会话，不会自动复制父会话的全部历史和附件，也不会扩大原有资源权限。详见[协作方式与限制](../03-features/26-weknora-assistant.md#collaboration)。

## 自动化：让任务按时间执行 {#automations}

每天整理资讯、定期汇总资料、检查知识库状态，都可以保存为自动化任务。支持一次性执行与 Cron 周期计划，可指定时区、模型、会话方式和通知选项。

告诉助手要做什么、何时执行，即可用对话设置任务；也可在自动化页面逐项填写，检查计划后保存。

<Screenshot src="/screenshots/automation-conversation.png" caption="一句话设置：由助手整理任务和执行计划，供你确认" />

<Screenshot src="/screenshots/automation-setup.png" caption="手动设置：选择重复频率、时间和时区，查看下次运行预览" />

自动化由 WeKnora 助手以创建者身份执行。任务需要审批时暂停并通知你，运行结果和完整过程可从记录中查看；可以暂停计划、手动运行或取消一次执行。长期授权限定到任务、操作和资源范围，仍受当前权限检查。详见[自动化](../03-features/27-automations.md)。

## 执行权限与审批：决定哪些操作需要确认 {#permissions}

新增「只读」「修改前确认」「自动执行」三种执行权限，区分查询、一般写入与破坏性操作。选择自动执行后，删除等高影响操作及强制审批工具仍需确认；选择只读时，不能通过审批临时绕过写入限制。

<Screenshot src="/screenshots/assistant-permissions.png" caption="选择会话执行权限，并在审批时核对操作范围" />

待审批事项与可恢复的运行状态持久化，刷新页面后可以继续处理。会话授权和自动化长期授权各有范围，权限变更与撤销仍然生效。详见[执行权限与审批](../03-features/28-agent-permissions.md)。

## 沙箱与后台任务 {#sandbox}

- **按用户复用沙箱**：部署者可显式开启，同一用户与配置可复用机器，不同会话保留各自工作目录；默认仍按会话分配。
- **后台 Shell**：长命令可以交给后台任务执行，查看输出、等待结果或取消，不必依靠 `nohup` 或手动脱离进程。
- **技能更新策略**：按会话分配时，可选择下一轮或新会话使用更新；按用户复用时，不会因技能更新自动重建正在使用的机器。
- **Lite 本机执行**：默认会话目录迁移到用户目录下的 `.weknora/sessions`；本机删除与扩大沙箱访问范围有更明确的审批。

共享机器中的会话目录不是操作系统级隔离。启用条件、已有会话行为和回滚注意事项见[技能与沙箱](../03-features/22-skills-sandbox.md#user-sandbox)。

## 数据源、解析与检索 {#knowledge}

- **飞书 / Lark**：文档默认使用 blocks 解析，改进表格、图片、附件和目录同步；可在数据源设置中选择解析方式。
- **钉钉 / Confluence**：钉钉支持按需保留目录结构；Confluence Server / Data Center 支持 PAT 认证。
- **图片处理**：图像处理流程支持更细的配置，可按知识库启用 OCR 图片预处理。
- **表格与网页**：Excel 可选择按显示百分比输出文本；HTML 可选择正文提取，默认行为保持不变。
- **检索**：补充 RRF 融合设置、文档范围 MCP 搜索和知识图谱 JSON 接口，修复多维度向量隔离与检索错误处理。
- **FAQ**：列表可切换展开方式，便于浏览与维护问答内容。

详见[文档解析](../03-features/03-document-parsing.md)、[数据源](../03-features/10-datasource.md)、[飞书云文档](../03-features/24-feishu-drive.md)与[检索引擎](../03-features/05-retrieval-engines.md)。

## 其他改进与修复 {#other-changes}

- **模型与流式回答**：改进 SSE、多行数据、推理内容和拒答信息的兼容处理，减少异常流导致的内容丢失。
- **空间默认设置**：在「设置 → 默认设置」选择对话、辅助任务、向量、重排、视觉和语音模型，以及默认联网搜索服务。已在智能体、知识库或任务中明确选择的模型优先使用。详见[设置空间默认模型](../03-features/06-models.md#workspace-defaults)。
- **工具调用与完成状态**：识别并校验 OpenAI 兼容响应中的 DSML 工具调用；保留 Ollama 的结束原因，MCP 对话流缺少完成事件时报告错误；最终回答汇总关闭额外思考，限制 WeKnoraCloud 视觉响应大小。
- **文档处理**：改进 Office、PDF、EPUB、CSV 与图片的解析，限制异常文件的内存消耗，完善取消、重试和失败反馈。
- **内容与检索修复**：助手维护 Markdown 时保留缩进和换行；Lite 遇到分词后为空的查询时跳过全文检索，继续向量检索；修正 BLEU 与 NDCG 的评估计算。
- **同步与访问**：修复游标与删除对账、附件下载和资源范围检查，改进受限请求的处理。
- **会话与界面**：改进附件、工具结果、协作状态和后台任务的展示，完善助手在不同页面中的交互。
- **审批等待**：可持久化的审批直接显示等待状态及可用时的到期时间，不再把短暂的后台等待显示为用户必须处理的倒计时。
- **IM、CLI 与 SDK**：修复群聊提及目标、渠道消息处理、命令行和客户端的兼容问题。
- **网站**：新增助手、自动化、执行权限文档与本版本说明，更新配置、API、架构和数据库迁移指引。

## 升级须知 {#upgrade-notes}

### 升级前

1. 备份数据库、文件存储与部署配置；需要保留的沙箱工作文件也应单独备份。
2. 核对镜像版本与迁移条件。v0.8.3 之后新增 PostgreSQL `000119–000134`、SQLite `000037–000051` 迁移，涉及审批、助手、协作、自动化、沙箱分配和空间默认模型。
3. 检查助手与普通智能体的执行权限上限、MCP 工具审批策略和自动化授权范围。

### 数据与配置变化

- **空间默认模型**：新增 `tenants.default_settings`，未设置时保留部署默认模型的回退行为；辅助任务模型留空时跟随对话默认。更改空间默认设置不会批量替换知识库或智能体中已保存的模型选择。
- **飞书 / Lark 重同步**：迁移会安排已有相关数据源重新同步，升级后留意任务量、解析服务和模型调用。新数据源默认 blocks 解析；原来显式配置的 export 模式仍保留。
- **空图片分块清理**：迁移会清理符合条件的历史空图片 caption、OCR 和向量分块；不是清空文档或原文件。
- **沙箱复用为显式开关**：`WEKNORA_SANDBOX_USER_ALLOCATION=enabled` 需要 Redis。应先完成所有应用副本升级，再开启；已有绑定和检查点不会强制迁移。启用后不能直接降级到不理解共享分配的旧版本。
- **日志格式变量**：优先使用 `WEKNORA_LOG_FORMAT`。只有它未设置时才回退到 `LOG_FORMAT`；非空模板需包含 `%msg`，显式空值表示不使用自定义格式。
- **默认容量**：`WEKNORA_TENANT_DEFAULT_STORAGE_QUOTA_MB` 可为新空间设置默认配额，现有空间不会仅因修改环境变量而改变。
- **解析选项**：OCR 预处理、HTML 正文提取和 Excel 百分比文本输出均需按需开启，不会自动重解析全部已有文档。
- **超时**：MinerU Cloud 每批处理默认预算调整为 30 分钟；网页抓取默认共享 3 分钟预算。需同时检查上游代理、任务调用方和服务端的超时。

### 更新镜像与验收

正式 tag 与镜像发布后，将 `.env` 中 `WEKNORA_VERSION` 设置为 `0.9.0`，再更新对应版本的部署文件并执行：

```bash
docker compose --profile full pull --policy always
docker compose --profile full up -d
docker compose ps
```

仅运行 `up -d` 可能继续复用本地旧镜像。升级后确认迁移完成、界面版本一致，抽查文档解析与检索，并用低风险任务验证助手审批、自动化通知和沙箱文件访问。具体部署方式见[安装部署](../01-getting-started/02-installation.md)。从更早版本升级时，还需阅读 [v0.8.3](v0.8.3.md#upgrade-notes) 与 [v0.8.2](v0.8.2.md#upgrade-notes) 的要求。
