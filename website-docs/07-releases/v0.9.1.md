# WeKnora v0.9.1

这一版可以直接对着聊天输入框说话。需要登录网站时，你可以在沙箱桌面接手，也可以从个人凭据保险库选用已保存的账号。开发者可以用图片检索知识库。平时在网页上查资料，也可以从全局搜索结果直接跳到命中的原文。

## 按住说话，改完文字再发送 {#voice}

编辑智能体，在**附件上传**中开启**语音上传**，选好 **ASR 模型**（语音识别模型），普通聊天输入框就会出现麦克风。第一次使用时允许浏览器访问麦克风。按住按钮说话，松开后，识别出的文字会插入草稿的光标位置。检查人名、日期，或者再补一句，然后点击发送。

<Screenshot src="/screenshots/release-v091-voice.png" caption="按住输入框旁的麦克风时，按钮显示录音时长" />

<Screenshot src="/screenshots/release-v091-dictation.png" caption="松开后，这句关于报名截止时间的提问已经在输入框里，可以继续修改" />

也可以按住 `Alt + 空格` 录音，macOS 使用 `Option + 空格`。网页需要通过 HTTPS 或 localhost 打开。

## 在沙箱桌面登录，智能体继续同一任务 {#sandbox}

假设你让智能体打开活动报名系统、统计剩余名额。遇到登录页时，打开当前会话的沙箱桌面，亲自登录。回到对话，就能让它接着查看刚才的页面。在支持会话桌面的沙箱中，人和智能体用的是同一个浏览器，每个会话拥有独立的桌面和登录状态。

<Screenshot src="/screenshots/release-v091-login.png" caption="智能体打开读书会报名系统后，在对话中请求填写该站点的登录信息" />

使用 Lite 的本机工具时，可以按会话开启模型审查。授权写入工作区外的文件时，授权只适用于确认过的文件和写入内容。[技能与沙箱](../03-features/22-skills-sandbox.md#session-browser)

## 个人凭据保险库，下次登录直接选账号 {#vault}

如果每周都让智能体去同一个报名系统查名额，可以把账号保存一次。第一次在对话的登录表单里填写账号密码时，默认是**仅用一次**。选**保存到保险库**再点**填写**，下次这个站点请求登录时，就能从**已保存的账号**中选用。

<Screenshot src="/screenshots/release-v091-vault-fill.png" caption="再次登录读书会报名系统时，选中已保存的账号，核对域名后点「填写」" />

在**设置 → 账户 → 凭据保险库**可以直接添加账号、更新密码、调整允许填入的域名，也可以删除条目。账号按用户和工作空间分开，密码加密保存。你确认填写后，服务端把密码填到获得授权的 HTTPS 登录页，聊天里只需交代要办的事。

<Screenshot src="/screenshots/release-v091-vault.png" caption="在个人设置中查看读书会账号及其允许填入的域名，也可以编辑或删除它" />

自行部署时，需要为保险库配置固定的 32 字节 `SYSTEM_AES_KEY`，升级时保留原值。[使用凭据保险库](../03-features/22-skills-sandbox.md#credential-vault)

## 用图片检索，在全局搜索中直达原文 {#images}

**用一张图找相似图片。** 开发者调用 `POST /api/v1/knowledge-search` 时，可以只传一张图。例如，用一张设备照片找知识库里外观相似的图片。也可以同时传文字，让文字参与关键词搜索和重排。知识库需要配置支持图片的多模态嵌入模型，并已建立图片向量索引。[检索 API](../04-api/02-api-chat.md#post-api-v1-knowledge-search)

**从搜索结果读到原文。** 在全局搜索里输入「活动报名」，点开一条命中的文档片段，阅读器会直接定位到这段文字，可以连着上下文核对截止时间。跨库问答时，回答引用还会显示来源知识库。

<Screenshot src="/screenshots/release-v091-search.png" caption="在全局搜索中查找「活动报名」，从结果里选择《秋季共读活动手册》" />

<Screenshot src="/screenshots/release-v091-source.png" caption="点击这条结果后，阅读器定位并高亮手册中的报名截止时间" />

## 重建知识库时，旧内容保留到哪一步 {#knowledge}

批量重新解析文档时，排队和读取文档期间，原来的内容仍能搜到。读取失败也会保留旧内容。等到开始用新分块重建索引时才会清理旧分块。如果索引在这个阶段写入失败，需要从处理记录排查并重试。[文档处理与进度](../03-features/02-knowledge-base.md)

使用 PostgreSQL 并开启自动迁移时，首次写入或查询某个受支持的向量维度，会在后台按需创建 HNSW 索引。例如使用 1536、2560 或 3072 维的嵌入模型，部署者无需为这些维度逐个手工建索引。

## 从 v0.9.0 升级 {#upgrade-notes}

1. **先备份。** 备份 PostgreSQL 或已停止写入的 Lite 数据库、文件存储和部署配置。保留原有加密密钥，以及需要带回的沙箱工作文件。
2. **更新整套镜像。** 使用目标版本的部署文件。Compose 在 `.env` 中设置 `WEKNORA_VERSION=v0.9.1`，执行 `docker compose pull` 和 `docker compose up -d`。使用沙箱时，也要更新对应的运行镜像或提供商桌面模板。Helm 包 `0.1.1` 默认选择 `v0.9.1`。如果自行覆盖过组件镜像标签，请一起检查。[安装与部署](../01-getting-started/02-installation.md)
3. **检查数据库迁移。** PostgreSQL 从 `000134` 到 `000137`，SQLite 从 `000051` 到 `000053`。本次增加个人凭据表、调整 IM 会话映射索引，并在 PostgreSQL 上扩展审计记录的用户标识字段。升级后核对原有资料检索、IM 会话和迁移状态。[数据库版本对照](../06-development/02-database-schema.md)
4. **使用个人凭据保险库的部署**需要固定的 32 字节 `SYSTEM_AES_KEY`。各服务副本使用同一个值，重启和升级时保留原值，并与数据库一同做好备份。
5. **需要回退时**，停止新版本写入，使用升级前备份恢复数据库、存储和配置，再切回 v0.9.0 镜像。新增的 IM 线程映射可能不符合旧版唯一约束，向下迁移还会删除个人凭据表，并在 PostgreSQL 上截短超过 36 个字符的审计用户标识。恢复备份前，先保全升级后需要留存的数据。
